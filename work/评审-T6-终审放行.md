## 2. 唯一高危阻断 H1：raw request 可关闭化身门

### 2.1 定位与根因

1. [kit index:305–320](<../packages/dsh-vscode-kit/src/index.js#L305-L320>)：仅 `vscode.applyEdit` 糖衣调用 `assertLocalExpectedIncarnation` 和 `_assertAnchorSource`。
2. [kit index:986–1066](<../packages/dsh-vscode-kit/src/index.js#L986-L1066>)：公开 `request('vscode.applyEdit', …)` 有 grant、会话、版本协议及能力门，**没有**前述化身必填检查。对端明确公告 `document-incarnation` 也不例外。
3. [桥端 capabilities:334–343](<../packages/dsh-kit-bridge/src/capabilities.js#L334-L343>)：`expectedIncarnation === undefined` 直接放行；[880–882](<../packages/dsh-kit-bridge/src/capabilities.js#L880-L882>)只在已提供时比化身。
4. [事务:171–191](<../packages/dsh-kit-bridge/src/edit-transaction.js#L171-L191>)：两道比较确在同一同步 callback，但化身比较以 `expectedIncarnation !== undefined` 为条件。省略后成为纯整数版本检查。
5. [真实适配器:299–308](<../packages/dsh-kit-bridge/src/vscode-host.js#L299-L308>)原样传递可选字段，没有补上强制性。不是“假宿主漏掉了产品判定”。

因此不能以“糖衣缺字段会拒绝”“事务化身测试通过”证明所有公开写入口都安全。这里与 expectedVersion 不同：raw 缺版本会被桥端必填检查拒绝，raw 缺化身却会被桥端和事务共同接受。

契约关系：权威契约 **§6.1.1 ② 的 generic request 不得免检 / 同链路原则**适用于写能力入口；七行 **grant 判定本身仍成立**，本 finding 不声称绕过了它。被破坏的是题设明确要求的“版本与化身两道门”及 [M0 §2.4](<协作编辑-M0复核与保守裁决.md#L19>)不覆盖人工内容的目标；既有 grant 不能替代内容锚点。

### 2.2 未变异源码独立复现 A：跨窗口，无需生命周期假设

准备：两条已准入且协议版本 1 的连接，A 先连、B 后连，**两端均公告化身支持**。会话 S 的 grant 绑定 A。A 文档为 v7 / inc-A，首行为 `HUMAN`；B 文档为 v7 / inc-B，首行为 `line1`。使用仓内既有 [a.txt](<t32-fixture/a.txt>)作真实路径，缓冲区为独立内存状态。

1. 无 session 的 `kit.vscode.getDocumentState({file, includeText:true})` 按活跃视角读取 B，得到 v7 / inc-B。
2. 公开 `kit.request('vscode.applyEdit', {file, expectedVersion:7, range:第一行1到6列, text:'DSH!!'}, {sessionId:S})`；故意/遗漏不传 `expectedIncarnation`。
3. 写请求正确路由 A，但 A 的 v7 与 B 的 v7 相等；化身被省略，真实事务构造一次编辑。
4. A 的 `HUMAN` 被覆盖，仍返回 `applied:true, saved:false`。

本轮原始输出摘要（探针命令 exit 0 表示成功断言漏洞存在，不是安全通过）：

```json
{"case":"T6-CROSS-WINDOW-RAW","readFrom":"B","writeTo":"A","bothAdvertiseIncarnation":true,"anchorB":"inc-B","versionB":7,"beforeA":"HUMAN\nline2\nline3\n","afterA":"DSH!!\nline2\nline3\n","frames":{"A":1,"B":0},"result":{"applied":true,"saved":false,"textLength":5},"diskTouched":false}
```

“写帧仍只到 grant 窗口”不是反驳：错误是**按 B 的坐标视图覆盖 A 中人工内容**，不是 socket 投给了 B。无需攻击者、无需猜 token、无需权限升级；正常第三方消费者使用公开 request 并漏字段即可触发。

### 2.3 未变异源码独立复现 B：重开实例数字复用

同一 grant/连接，先读取 v1 / inc-original；测试宿主换成 v1 / inc-reopened，首行为 `HUMAN`。同一份缺化身请求：

```json
{"case":"T6-RAW-MISSING-INCARNATION","feature":"document-incarnation","actualIncarnation":"inc-reopened","sugarRejected":true,"rawResult":{"applied":true,"saved":false,"textLength":5},"constructs":1,"buffer":"DSH!!\nline2\nline3\n","diskTouched":false}
```

### 2.4 修复后重审门（本轮不实施）

- 对声明化身支持的写目标，把必填与来源检查放到 raw / 对象 / 位置入口共有的发送路径；扩展真实写入路径也必须拒绝缺化身，不能把安全不变量只寄托在糖衣。
- 对不能提供化身/CAS 的旧端，不可静默放宽为同等安全的自动编辑；明确降级为拒写，或另行获得收窄范围的裁决。
- 新增回归必须真正调用公开 raw request，重放上面两场景，断言零 edit/人工字保留；同时覆盖糖衣两形态。不是把四份等价 params 喂给同一个下层 handler就算“四入口”。
- 去掉任一新强制检查后，应有对应回归变红；然后完整复跑四门再由独立评审判卷。不能只改注释、要求消费者自觉传字段，或删除现有能复现问题的特征化用例。

## 4. 权限、路径、凭证、并发的独立判断

- **会话+窗口**：程序化绑定成立。session 从本地 opts 与记录比对，业务 params.sessionId 被拒；窗口安全身份是投递连接对象，不是 windowId 标签。grant 到哪个扩展进程就只存在那里，关闭/重连使旧记录失效。阶段发放走 stage → 回执 → activate，pending 不参与放行。
- **真实授权边界不能夸大**：opts.sessionId 仍由可信消费者提供，不是从 Harness 的不可伪造执行上下文取出的身份；没有 per-plugin 权限隔离，也没有本期人可见授予确认 UI。申请时 [grantEditing:781–811](<../packages/dsh-vscode-kit/src/index.js#L781-L811>)选当前已准入连接，windowId 仅标签。不能把“会话字符串比对”说成抵御恶意同进程插件的认证；权威契约 §6 已明确无 per-plugin 授权，§1 又把“谁能授权”留给上层。
- **凭证**：id/epoch 用随机 128-bit 值，进程内表，墓碑不放行；token 按消息鉴权，请求自动带、通知/响应默认不带。每连接 pending 隔离，所以“响应无 token 比较”不等于另一 socket 可答掉本连接请求。源码与四门均覆盖该边界。本轮未读实际发现文件或真实 token。
- **路径**：[workspace-paths:176–255](<../packages/dsh-kit-bridge/src/workspace-paths.js#L176-L255>)拒多根，按段判断根内，根祖先至文件逐段 lstat，拒 symlink/junction；写前再验，写后采样及文档身份校验。不能保证同用户进程在检查与编辑器异步准备间替换路径的原子安全；README 如实排除这一威胁，未据该已声明边界新报漏洞。
- **版本+化身原子区间**：两参数均存在时，同一份 editor.document 在同步 callback 内读、比、构造，无 await；真实适配器调用 TextEditor.edit 而非 WorkspaceEdit。对主线程竞争仍依赖 VS Code 自己的版本 CAS，不是“扩展进程同步”单独阻止所有输入。**化身可缺**使这一性质无法覆盖全部写入口，H1。
- **串行化**：[锁键:258–260](<../packages/dsh-kit-bridge/src/capabilities.js#L258-L260>)仅 Windows 全小写，其他平台不折叠；[入队:859–862](<../packages/dsh-kit-bridge/src/capabilities.js#L859-L862>)实际使用此键；不同文件不共锁。Windows 大小写别名实跑未 skip，M3 可使其变红。本轮不声称 macOS 默认不区分大小写卷的同等保障。
- **getDocumentState 会不会探别的窗口**：有 session 的 stateFor/绑定读，只找该 session 的有效 grant，失效不回退；无 session 刻意读取活跃窗口，且不要求写 grant。因此“无 A 写权就不能读 B”**不是当前读权限模型**；已准入可信消费者可读活跃 B 的工作区文本，不是新发现的未经读授权网络泄露。给 session 的路径已修正 T5 路由问题，**无 session 读B + raw漏化身写A**仍是 H1。
