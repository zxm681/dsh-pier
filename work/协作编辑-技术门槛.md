## 威胁模型与最小 API 契约（提议，尚不存在）

**资产**：主树和人的 dirty buffer/未跟踪内容、DSH 树、发现文件 token、会话编辑 grant、提交 SHA、GUI 差异。**攻击者/干扰源**：同用户恶意进程与读发现文件者、其他 VS Code 窗口/扩展、符号链接/junction 修改者、迟到响应和断线重连。**边界**：浏览器 GUI ↔ DSH 会话认证；DSH 插件 ↔ 裸 TCP 实例 token；扩展 ↔ 受信任工作区需独立 grant；buffer/磁盘/index 绝不混同。Windows chmod 在 `packages/dsh-vscode-kit/src/discovery.js:45-55` best-effort，不能充当强 ACL；实际 token 不回传。旧审计未结案，跨进程可达性保持未独立验收。

提议唯一初始写入口 `vscode.editText({target:{windowId,workspaceId,relativePath},expected:{documentVersion,contentHash},edits:[{range,text}],grantEpoch,operationId}) -> {applied,documentVersion,isDirty,operationId}`。禁止该接口内自动 save、Git、文件创建/删除/重命名、任意盘符目标。授予/撤销须在人可见的**VS Code 可信 UI**，绝非 DSH 或网页自授；grant 绑定 DSH session + authorized link + window + 物理根 + epoch；断线/失信任/关窗清空。扩展在每次写前重新核验 trust/grant/真实路径/文档版本/hash，operationId 做幂等；不明返回 `UNAUTHORIZED / UNTRUSTED_WORKSPACE / PATH_OUTSIDE / STALE_BUFFER / HUMAN_INTERVENTION / AMBIGUOUS_TARGET / DISCONNECTED`。核验和 applyEdit 之间原子性目前**未证**，需专门竞态夹具。

**方案权衡**：A 优先禁链接/多窗口写，任一外来变化冻结该文件；简单可审计，但链接内合法文件/格式化器会被拒。B 开放链接、多窗口、细粒度归属，需可靠句柄约束/来源证明和跨窗口真机竞态；自由度大但审计成本与误写风险高。A 仍须通过撤销与 TOCTOU 门，不是当前 GO。

## ADR-001（提议）：分离连接准入和自动写许可

**背景**：现有 token 仅连接准入，原 phase2 排除编辑；本地同用户进程和多个窗口不等于人授权。**决策**：候选双门：连接 token + 人授予且可撤销、绑定会话/窗口/真实根的短期 grant；缺一拒绝。**备选**：只沿用 token（简单，但泄露或错路由直接变写权）；每次 modal 确认（保守，但不满足连续自动编辑）。**影响**：引入 epoch/竞态及交互成本，换取可见可撤销的失败闭合边界。**状态**：提议中，等待裁决和真机负例。
