## 分阶段任务（每项预计 30–60 分钟的一个聚焦交付；未能在一轮证明则标 NO-GO 再拆，不把门槛跳过去）

### T1 软件架构师｜技术可行性与安全设计门槛（无实现）
**目标**：以源码/API 小型只读探针与先例调研形成 GO/NO-GO 决策记录：扩展工作区信任/会话授权撤销与在途写竞争，路径归一化、符号链接/junction 与 rename 逃逸，buffer 与磁盘差异及人工/自动编辑归属可判性，多窗口路由、Web GUI 侧栏通道、Git 双 worktree 生命周期和独立预演的可行边界；明确 token/连接准入及失败即拒绝。**验收**：逐项标已证实/待验证/不可行，给出威胁模型、最小 API 契约和复现实验、源码 SHA/提交时间，列出用户决策门及退出条件；无编辑/删除/自动提交代码。**依赖**：旧板 T3 安全审计结论先读；只读研究可与旧任务并行，但任何探针写入共用工作树必须串行。**范围**：新增本阶段设计/证据文档于 `docs/` 或 `work/`，不修改旧 README/phase2/协议补丁。**风险**：未裁决项不能偷换成技术默认值。

### T2 Git 工作流大师｜双分支/双工作树隔离的最小准备
**目标**：仅在 T1 GO、用户决定工作树路径/生命周期且旧写型任务停止后，设计并验证 Git CLI（非假定工具 create_worktree）能把人的原窗口留在原分支、DSH 置于独立 worktree，绝不搬运/清理现有未提交内容；保留失败回滚与污染检测证据。**验收**：隔离试验显示不同工作树/分支的修改互不污染、原窗口不切分支/不抢焦点；面对已有修改安全拒绝或中止，不执行 `git restore`/`git checkout --`/清理；结果记录路径、状态与失败语义。**依赖**：T1 GO 与共享工作树独占写窗。**范围**：审批后的隔离资源/测试，不做编辑、提交、推送、合并。**风险**：当前只有 main 和未提交内容，需人裁决如何保全人的工作树。

### T3 后端架构师｜会话授权文本编辑的最小垂直切片
**目标**：T2 隔离后，基于现有 DSH facade → 裸 TCP 协议 → VS Code 能力分派 → 编辑器缓冲区走通**单文件文本修改**，仅受信任工作区、明确会话授权、路径限域；第一版任何外部/人工交错或归属不明均停该文件并请求人确认，不自动保存/删除/新建/改名。**验收**：授权前/撤销后/失去信任/路径逃逸均失败；撤销与在途操作按 T1 裁定的线性化规则可测且不留越权写；人原窗口不切分支；只声称缓冲区改变，绝不称磁盘已验。**依赖**：T1、T2 与决策门明确。**范围**：桥接能力最窄公开 API + 对应单测，不能无依据重写 protocol.js。**风险**：连接已鉴权不等于会话编辑获准；符号链接与并发 TOCTOU 需失败闭合。

### T4 后端架构师｜人工介入归属、保存/磁盘验证边界
**目标**：在 T3 单文件路径上验证人工改动/混合归属监测及保守停止；仅 DSH 独立修改文本允许检查点前自动保存；磁盘测试标记实际快照，对人的文件不自动保存、暂存或提交，其他文件不受阻。**验收**：人工交错内容字节不丢、归属未知时不覆盖/保存/提交；人工介入提示包含动机/合理性/风险/助益与待确认建议（建议文本可由上层形成，不能冒充确定归属）；未保存内容不被报告为磁盘测试通过；单测/E2E 验证自有文本可保存且人工文件不保存。**依赖**：T3；共享源码修改串行。**范围**：有限文本与验证报告；新建/删除/重命名、删除升档与临时集成仍不开启。**风险**：若同缓冲区编辑归属无法可靠识别则 NO-GO，维持停写而非猜测。

### T5 安全工程师｜安全与并发回归验证门
**目标**：在 T3/T4 稳定后，独立设计授权撤销竞争、路径越界（大小写/符号链接/junction/rename）、多连接错路由、人机交错、未保存磁盘测试误报、未跟踪/脏内容删除被拒的负例；对本切片未实现的删除操作验证拒绝而非假装支持。**验收**：负例能用故意恢复对应漏洞的变异试验变红且修复后变绿；运行 AGENTS 所列三包 `node --test "test/*.test.js"` 与 bridge `node scripts/e2e.mjs`，涉及真实 VS Code API 做真机验，附命令/退出码/证据；发现不可信权限边界则 NO-GO。**依赖**：T3、T4；测试 fixture 写入要与旧板写任务及实施串行。**范围**：测试/证据与必要修复建议，不替实施专家悄悄改产品行为。**风险**：当前源码测试历史计数不等于本阶段覆盖。

### T6 代码审查员｜独立安全/代码评审及阶段放行建议
**目标**：独立于 T3/T4 实施者审查 T1 决策、T2 工作树隔离、T3/T4 代码与 T5 原始验证证据；安全工程师协同复核撤销/路径/凭证/并发威胁模型。**验收**：逐项记录可复现 findings、影响、修复后复审结果和 GO/NO-GO；不以测试全绿替代审查，不批准未解决高危缺陷；结论明确 UI/删除/预演尚未实施，交人决定下一期范围。**依赖**：T5。**范围**：独立评审报告，不实施 UI、删除升档、集成或部署。**风险**：不能由实施者自审放行。

## 依赖、里程碑和串行冲突

`旧板 T3 安全审计收口/旧写型任务让出工作树` → `T1 GO/NO-GO + 用户决策` → `T2 隔离` → `T3 单文件可撤销文本编辑` → `T4 人工归属/保存边界` → `T5 负例、变异、真机` → `T6 独立评审`。T1 的**只读**调研可与旧板审计只读工作并行；T2–T5 同享 `packages/`、测试夹具与当前工作树，互相和旧板任何写型工作**串行**；T6 可在评审窗口只读，不得与在途补丁混审。里程碑 M0=安全基线与可行性裁决，M1=隔离，M2=最小垂直切片，M3=归属/验证，M4=独立评审。每关 NO-GO 则暂停下游，不用假通过解锁。

## 待用户裁决 / 后续可推迟能力

1. **会话授权**：谁授予/撤销、作用于哪个 VS Code 窗口与 DSH 会话、重连/信任丧失时是否立即失效，以及撤销与已经发起但未落盘的写操作如何定线性化点。未裁决前禁止自动写。
2. **路径与归属**：工作区多根/大小写/链接/junction/路径更名如何取真实根；同一缓冲区交错修改不能辨别来源时是否统一停写待确认（建议保守停写）；人的脏内容保全与新 DSH worktree 路径由人选择。
3. **删除**：默认逐次确认；删除档位的级数、升档 UI/权限恢复与会话终止回退、普通/高风险识别（含未保存/未跟踪/未提交）需单独审批、测试与独立安全评审；高风险始终列明路径逐次确认，不能承诺 Git 撤销可靠恢复。**本轮只测拒绝，不交付删除。**新建/重命名即时落盘同样留待下阶段。
4. **Web GUI/集成**：侧栏实时进度/差异摘要的数据来源与认证机制、按需第二窗口及焦点保护、已提交双方内容进入独立临时工作树预演的前置条件与冲突人工确认、未提交/未保存排除提示需技术验证后**另起独立草案**；最终合并/提交仅人决定。不把裸 TCP 假装 HTTP/WS，也不偷用并不存在的 create_worktree 工具。

**范围外**：推送远端、自动合并、替人保存/提交、常驻第二窗口、永久备份/恢复保证、跨工作区/不受信任工作区写入、未经人主动逐级升档的删除、假设原始 `phase2` 已包含编辑、改旧项目板/旧未提交文件。无正式时间线写在规格里；30–60 分钟仅是**每任务聚焦研究/实现/验收回合**的估算，遇 NO-GO 需拆分再评，不许以工时压力绕安全门。
