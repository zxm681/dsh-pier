## 3. 与任务书的**两处有意偏离**（必须说清，不是漏做）

### 偏离 1：写调用**不带** `target`（任务书第 5/6 步的写法照抄会必然失败）

任务书写"用 A 的最新 version + incarnation 调 `applyEdit`"，并给了 `{target: W.windowId}`。
**已上线合同禁止写路径带窗口寻址**，照抄会得到 `-32014`，且是 DSH 侧本地抛、对端一帧都收不到：

- `packages/dsh-vscode-kit/src/index.js:808-822`（`applyEditAs`）第一步就是
  `this._rejectWriteWindowTarget('vscode.applyEdit', opts)` → `index.js:956-963` 抛
  `-32014` `reason:'target-not-routable'`，`data:{write:true,boundBy:'grant'}`；
  `request()` 里同一条判（`index.js:1967-1973`）。`saveAs`（849）/`deleteFileAs`（887）同构。
- 写目标由 **grant 记录的 link** 决定，只来自 `_bindWriteTarget(params, sessionId)`（`index.js:978-993`），
  **绝不回退 `_activeLink()`**（AGENTS.md 铁律 12 也这么写）。

⇒ 探针的做法：
- **读**（`vscode.openFile`）带 `target: W.windowId` —— 读路径寻址是合法的；
- **写**（`vscode.applyEdit`）**只传 1 个实参**，没有 opts、没有 target。冒烟里专门有一条断言守它（§8 M2）。

### 偏离 2：`openFile` 只在首轮 / 换窗口时打，不是每轮都打

任务书写"每轮依次打开 A 与 B"。照做的话 5 秒一次 `openFile` 会**反复抢焦点**，
而本轮验证的核心恰恰是"主人在 A 里敲字"——每 5 秒把他正在敲的编辑器重新激活一次是自毁场景。
探针改为：首轮打开一次，之后仅在"目标窗口变了"时重开。挑窗口/绑授权/读锚点/写测试**仍是每轮都做**。

## 4. 探针设计要点（`index.cjs`，593 行，零依赖 CJS，不 import 'vscode'）

### 4.1 接线形态（抄现有先例，不发明）

```js
const name = 'dsh-a2-probe';
const inject = ['dshVscodeKit'];
function apply(ctx) { const svc = ctx.get('dshVscodeKit');
  const kit = typeof svc.forPlugin === 'function'
    ? svc.forPlugin('dsh-a2-probe', { declared: 'buffer-edit' }) : svc; ... }
module.exports = { name, inject, apply };
```
与 `dsh-multiwin-probe` / `dsh-events-probe` 完全同构。`forPlugin('dsh-a2-probe')` 的名字与
`consumers: { dsh-a2-probe: buffer-edit }` 的键**逐字一致**（不一致会被白名单判回 `read`，
`applyEdit` 直接死在白名单而不是脏门——那会得到一个假结论）。

`apply` 里任何取服务的失败都进 `bootErrors` 落盘，**绝不抛给宿主插件树**（一个验证探针不能把 DSH 带崩）。

### 4.2 锚点必须来自**绑定读**

`_markBoundRead`（`index.js:1439-1459`）把 `incarnation` 记在 `_anchorSources` 里，`_assertAnchorSource`
（`index.js:1482-1525`）会校验"锚点来源的 link == 写目标的 link"，不一致 → `-32602 anchor-source-mismatch`。
所以探针**只用** `kit.editing.stateFor('a2-probe-session', file)` 读锚点（走 grant 的那条 link），
`getDocumentState({file},{target})` 只用于展示、绝不当写锚点。

### 4.3 A 的写测试只在 `isDirty === true` 时发一次

- `isDirty !== true` → 一个字节都不发（冒烟 M3 专门守这条：把判据删掉就变红）。
- 判序提醒：`judge()`（`document-write-policy.js:332-404`）① 已有 taint 先拒（`reason = taint.reason`），
  ⑤ 才是"脏 + 无 dirty 许可 → `dirty-quarantine`"。主人敲字会先触发 `noteChange` 的归属推断
  （`inflight === 0` 且版本变了 → 判 `foreign-change` 并冻结），所以真机上 A 的 reason 可能是
  **`foreign-change`** 而不是 `dirty-quarantine`——**两个都是 `-32011`，都算 A2 生效**，报告按实测记。
- 探针给 grant **不传 `allowDirtySave`**（缺省 false），这样验的是"默认档就是拒"，而不是"开了许可所以能写"。

### 4.4 B 的写测试只在"干净"时发一次

B 干净 → 走判序 ③ 放行。注意写成功后 **B 变脏**，所以只发一次；结果落 `applied:saved-false` 与新的 `textLength`。

### 4.5 `-32012` 不算结论

`expectedVersion`/`expectedIncarnation` 是"读到就得等值"的快照语义。人还在敲字时上一轮的锚点会立刻过期，
探针把 `-32012` 当作"再等一轮"，**不写任何 verdict**，避免把"主人在打字"误判成"门坏了"。

### 4.6 落盘是**原子写**

`writeAtomic()`：`mkdir -p` → 写 `.a2-probe.json.tmp-<pid>-<ts>` → `fsync` → `rename`。
主人可能在任何时刻点开这个 JSON，所以不允许出现半个文件。冒烟断言"无 `.tmp-` 残留 + 文件以 `}` 收尾"。

### 4.7 异常原样落盘，不许洗成成功

`errInfo(e)` 摊平 `code / name / message / data / stage / method / reason`，对象没这些字段就退回
`stringified` + `keys`，null/undefined/原始值各给形状。verdict 只有在"真的拿到 `applied:true`"时才写
`applied:*`。**M1 变异就是故意在 catch 里伪造 `applied:true`，冒烟立刻变红**（§8）。

### 4.8 定时器纪律

递归 `setTimeout` + `timer.unref()`（铁律 4：库不许延长宿主进程寿命）；`stopped` 标志防重入；
达成 done 后**不再排下一轮**（冒烟断言"done 之后定时器数量为 0"）。

### 4.9 轮次记录上限

`MAX_ROUNDS_KEPT = 40`（保留最近 40 轮明细，`round` 计数与 verdict 全留），避免 120 轮把 JSON 撑到几 MB。

## 9. 顺带核实到的源码关切（**不是本轮要修的，交给实现者/评审判断**）

1. **`establishBaseline` 没有生产调用点。** `document-write-policy.js:313` 是唯一清 taint 的入口，
   但 `grep -rn establishBaseline packages/` 只命中"定义 / 导出 / 测试"。⇒ 运行期一旦被判
   `foreign-change` 冻结，除**重启进程 / 512 文件 LRU 淘汰**外不会解冻。v2 里"人明确交接后新建基线"
   这条恢复路径**没有接线**。真机上如果先敲字再试图写，A 的 reason 很可能就是这个原因（`foreign-change`）。
2. **`params.allowDirtySave` 全链无读者。** `capabilities.js` 的 `policyInput`（1118-1131）只看
   `grantAllowsDirtySave(grants, params?.grant)`；请求体上带 `allowDirtySave` 不产生任何效果。
   这是"只有一个判定处"的正确形态，但也意味着**调用方无法按次申请脏写许可**，只能靠 grant。
3. **`readStateFor` 与 `getDocumentState` 的守卫不同源。** 前者走 grant 的 link，后者可带 target；
   两者都能拿 `incarnation`，但**只有前者能当写锚点**（否则 `anchor-source-mismatch`）。文档里值得写死一句。
4. **`editing.grant({windowId})` 的 `windowId` 不决定写目标**（`index.js:1715` 恒取 `_activeLink()`）。
   契约里目前没写清这一点，本次真机就是被它挡了一轮（§1.5 证据 4，一个字节都没发、也没污染任何文档）。
   建议在 `docs/协作编辑-钩子契约.md` 的多窗口章节补一句"grant.windowId 仅为元数据，路由由 `_activeLink()` 决定"。
5. 与 A2 无关但会干扰判读：`openFile` **不走工作区根守卫**（`capabilities.js:1259-1287` 只做 `resolvePath` +
   `fileExists`），所以"能打开"不等于"能写"。真机上若出现 `outside-workspace`，是**写/绑定读**的守卫在拒，
   不是打开失败——本次通电里 `openFile` 全绿而 `stateFor` 报 `outside-workspace`，正好是这条的实证。
