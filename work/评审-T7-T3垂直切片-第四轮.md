### 3.1 R3-1：闭合（文档身份校验与缺失失败闭合）

位置：[workspace-paths.js:399–433](<D:/code-workspace/projects/dsh-vscode-dev/packages/dsh-kit-bridge/src/workspace-paths.js#L399-L433>)、[capabilities.js:460–483](<D:/code-workspace/projects/dsh-vscode-dev/packages/dsh-kit-bridge/src/capabilities.js#L460-L483>)、[vscode-host.js:163–202](<D:/code-workspace/projects/dsh-vscode-dev/packages/dsh-kit-bridge/src/vscode-host.js#L163-L202>)。

- `assertWrittenDocumentIdentity` 读取 `outcome.documentPath`，不拿再次 realpath 冒充写入身份；比较对象为刚重验并原样传入宿主的 `writeTarget`。
- 真实适配器从已打开文档的 `uri.fsPath` 取身份；找不到时调用 `openTextDocument(uri)` 获取文档，异常或缺字段返回 null，不回退为 abs。
- 写后路径采样与身份复核均在构造成功结果之前。缺失、null、空串、空白、数字、对象六种身份均为 `-32603 document-identity-unavailable`；不会走到 applied:true。

独立 ABA：初次检查通过 → 宿主内把私有 Sub 换为 Outside junction → 对真实解析目标写入 → 摘掉 junction、恢复 Sub → 返回宿主记录的实际目标身份。原工作区文件仍为 original、Outside 内容已变为 ABA-WRITE，写后 realpath 已恢复原路径，handler **抛错而非返回成功**。

## 5. 非阻断的不同意见

**不据此判 fail。**本轮未在真实 VS Code 实证物理越界静默写入；同用户目录替换的原子性已明确排除。本报告接受这一裁决，不要求磁盘直写、内核锁或句柄防护；独立 ABA 证明的是“宿主报告不同身份后 handler 不再报成功”，不是“所有编辑器都必然将 junction 物理目标反映为不同 URI”。
