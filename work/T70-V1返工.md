## 1. MF-01

### 1.1 缺陷原文

[终审 §3 MF-01:33–41](<V1-独立验收.md#L33-L41>)：

> save 的失败出口遗留 inflight，外来脏内容能被再次保存。
>
> beginWrite 后，只在宿主抛异常的 catch 里及成功路径末端 endWrite。宿主正常返回 saved:false、非布尔，或写后路径/文档身份检查抛异常，均绕过收尾。

原探针 [V1-save-failure.log:1–4](<V1-save-failure.log#L1-L4>) 确实显示 `inflight:1, dirtyOwned:true`，外来 v2 后又一次保存成功。已读完整169行终审及两份原始探针，不把 false 视作只在 mock 中存在：[真实宿主:429–445](<../packages/dsh-kit-bridge/src/vscode-host.js#L429-L445>) 原样回传 doc.save() 的布尔结果。

### 1.2 改法（file:line）与失败语义

1. [capabilities.js:1912–1914](<../packages/dsh-kit-bridge/src/capabilities.js#L1912-L1914>) 在 beginWrite 后立即进 try，覆盖宿主异常、false、畸形回执、路径复核、文档身份复核、写后观测、stat、日志及返回。
2. [capabilities.js:2016–2020](<../packages/dsh-kit-bridge/src/capabilities.js#L2016-L2020>) 是本次 save 唯一收尾点；删除原 catch 内/成功路径中的收尾，避免重复扣减 inflight。不会替其它持有者结束窗口。
3. finally 显式给 `{attribution: ATTRIBUTION.UNKNOWN}`，而不是 null。依据 [endWrite:338–344](<../packages/dsh-kit-bridge/src/document-write-policy.js#L338-L344>)，null 裁决、零事件会保留旧 dirtyOwned；unknown 才撤销未经证明的所有权。失败即使没收到事件，也不能继承人工确认过的旧脏内容身份。
4. **状态落点是 `dirtyOwned:false`，不是凭空制造 taint**：save 无账本因果裁决，回执不可靠不能证明宿主没改过脏内容；结束后无本次 inflight，脏文档命中 [契约:1200](<../docs/协作编辑-钩子契约.md#L1200>) 第⑥步 `attribution-unknown`。随后真实外来 v2 进入非 inflight 分支，形成 `foreign-change`。已有 taint 从不清除；干净写仍遵循原第③步，不新增错误码、不改变七步判序。
5. 错误形状保留：false 为 `-32603 host-save-failed`，非布尔为 `-32009`，路径/文档身份失败仍走原错误。不在写后补报“已阻止写入”的 -32011；save 无强 CAS 的上限仍同 [契约:1205–1206](<../docs/协作编辑-钩子契约.md#L1205-L1206>)。

## 2. MF-02

### 2.1 缺陷原文

[终审 §3 MF-02:43–50](<V1-独立验收.md#L43-L50>)：

> LRU 淘汰无条件丢 taint，人工交接不再唯一。
>
> 容量默认512，LRU 删除的是整条文件状态，未区分 tainted、inflight 或普通诊断。之后访问该文件会重建 taint:null。

原始 [容量探针:1–2](<V1-probes.log#L1-L2>) 为 `foreign-change` 拒绝变成 allowed:true。

### 2.2 改法（file:line）与选择理由

选择任务书 **① 受保护条目不计入可淘汰集合**：[document-write-policy.js:173–181](<../packages/dsh-kit-bridge/src/document-write-policy.js#L173-L181>) 仅淘汰无 taint、无 inflight 的其它条目。新条目也不在本轮淘汰：stateFor 返回后才会 markForeign/beginWrite，若先淘汰新对象，调用方会修改一个已脱离 Map 的孤儿，照样丢证据。

理由：冻结是安全证据，不是诊断缓存。最小修改保留同一 Map 与原五种 reason，不引新不可用态/第二份状态，也不改判序。[契约:1224–1226](<../docs/协作编辑-钩子契约.md#L1224-L1226>) 明定人工 establishBaseline 是唯一清除 taint 的入口；容量压力不是人工交接。受保护条目不会被删，因此不存在“重建时默认 taint:null”的清锁路径。原始初始化 taint:null 仅用于真正首次出现或可淘汰的无冻结状态。

**明确代价**：maxFiles=512 是软上限，不是内存硬上限。若受保护文件很多，Map 可超过512；保留到人工基线/写窗口结束后才重新进入可淘汰集合。未宣称内存占用严格有界，也未新增自动洗白。超大规模/长稳内存测试未验证。

### 2.3 回归用例

均直接 `createWritePolicy()`，**不缩小默认容量**：

- [容量用例:19–29](<../packages/dsh-kit-bridge/test/t70-policy-eviction.test.js#L19-L29>)：markForeign(A) → 干净 A 的 deleteFile 拒 foreign-change → 观察600个其它文件，确认真的发生 evicted → 同一输入仍拒 foreign-change；只有显式 establishBaseline 后可解除。
- [inflight 用例:31–45](<../packages/dsh-kit-bridge/test/t70-policy-eviction.test.js#L31-L45>)：A 两个 holder → 600个新文件 → inflight仍为2，v2事件正确计入窗口；两次end才归零且unknown撤销脏所有权，v3外来事件冻结。
- [全保护用例:47–58](<../packages/dsh-kit-bridge/test/t70-policy-eviction.test.js#L47-L58>)：600个受保护条目全部保留，随后新 beginWrite 状态也不能脱离 Map，防止“只保护旧条目、先丢新条目”的修复缺口。

### 2.4 变异（改回后红原文）

- **M3**：恢复原 `while (files.size > maxFiles) { const oldest=files.keys().next().value; files.delete(oldest); stats.evicted += 1 }` 整条删除。[M3 原文:1–46](<t70-mutation/M3.log#L1-L46>)：`ℹ tests 3 / ℹ pass 0 / ℹ fail 3`；`AssertionError [ERR_ASSERTION]: capacity must not turn frozen archive into allowed:true`；actual `{allowed:true, attribution:'unknown', reason:null, phase:'queue'}`，expected `{allowed:false, reason:'foreign-change', attribution:'unknown'}`。inflight用例另红 `capacity must not discard active holders`，`undefined !== 2`。
- **M4**：保留 inflight 防护，但在容量遍历遇 taint 时错误折叠重建 `files.set(oldest, {...candidate, taint:null})`，随后 continue。这是对“重建默认清 taint”的独立变异，不重复 M3 的整条删除。[M4 原文:1–37](<t70-mutation/M4.log#L1-L37>)：`ℹ tests 3 / ℹ pass 1 / ℹ fail 2`；同样红 `capacity must not turn frozen archive into allowed:true`，actual allowed:true/reason:null，expected allowed:false/foreign-change；inflight回归仍绿，证明区分了两条判据。
