## 重要项（必须修改）

### F1：可选字符串字段被错误扩成 nullable

- 严重度：**重要**。
- 位置：[response-contract.js:220–226](<../packages/dsh-vscode-kit/src/response-contract.js#L220-L226>)；字段登记在 [同文件:151](<../packages/dsh-vscode-kit/src/response-contract.js#L151>)。
- 问题：可选检查将 null 一律视作未提供，导致 `editors[0].languageId = null` 被放行；契约要求的是“可选字符串”，不是“字符串或 null”（[契约:229、234](<../docs/协作编辑-钩子契约.md#L229-L234>)）。`source` 的现有字符串谓词也被同一分支绕过。
- 独立复现：从真实 `createCapabilities(host).dispatch('vscode.listOpenEditors')` 取得合法响应，将第一个元素的 `languageId` 设为 null；`validateResponse()` 原样返回，无 -32009。对诊断 `source=null` 同样复现。数字类型已有拒绝测试，null 则漏过。
- 不存在“正常 handler 必须返回 null”的证据：真实宿主适配器在无可见编辑器时省略 languageId，否则读取文档 languageId（[vscode-host.js:119–124](<../packages/dsh-kit-bridge/src/vscode-host.js#L119-L124>)）；handler 仅对 undefined 省略该字段（[capabilities.js:208–214](<../packages/dsh-kit-bridge/src/capabilities.js#L208-L214>)）。不能用避免误伤作为擅自扩宽 null 类型的依据。
- 要求修法：区分未提供与显式 null；保留缺失/undefined 的可选语义，但对显式 null 执行字段类型谓词并拒绝。补充 languageId=null 的拒绝回归；明确 source 的可选类型并作同口径测试。不要修改 bridge handler 返回。
- 测试伴随问题：[response-contract.test.js:91–118](<../packages/dsh-vscode-kit/test/response-contract.test.js#L91-L118>) 标题写“缺失或为 null”，但测试体并未赋值 null，不能证明标题所称行为；应同步改正标题与用例。

### F2：got 与错误 message 回显响应中的数值/布尔值

- 严重度：**重要**（诊断最小化边界违约；不是已证实的字符串凭证泄露）。
- 位置：[response-contract.js:174–177](<../packages/dsh-vscode-kit/src/response-contract.js#L174-L177>)、[同文件:240–247](<../packages/dsh-vscode-kit/src/response-contract.js#L240-L247>)、[同文件:281–285](<../packages/dsh-vscode-kit/src/response-contract.js#L281-L285>)。
- 问题：契约只允许 typeof/键名摘要（[契约:220](<../docs/协作编辑-钩子契约.md#L220>)），但 `describeLeaf()` 对 number/boolean 使用 `String(value)`。响应中的值不仅进入 `data.got.value`，还进入错误 message。
- 独立复现：合法选区响应仅将 `end.line` 设为 `-8675309123`，得到 -32009；`JSON.stringify(err)` 包含该完整值，片段为 `"value":"number(-8675309123)"`，message 同样包含 `number(-8675309123) at end.line`。这是响应值回显，不是类型摘要。
- 要求修法：叶子摘要只返回类型（或固定的 missing 标记），不回显任何数值/布尔内容；message 也必须只组合脱敏摘要。增加数值哨兵的 `JSON.stringify(err)` 不包含性断言，并保留已有字符串秘密回归。

### 内存变异方法（可复现，无源码写入）

在项目根通过 `node --input-type=module` 执行下面代码；预期 exit 1。load hook 只替换进程内模块源码，不落盘，因此不存在恢复时覆盖他人改动的风险。

```js
import { registerHooks } from 'node:module'
registerHooks({ load(url, context, nextLoad) {
  const loaded = nextLoad(url, context)
  if (!url.endsWith('/src/response-contract.js')) return loaded
  const source = String(loaded.source)
  const needle = "['mode', oneOf(...OPEN_MODES), 'mode:in{text,external}']"
  if (!source.includes(needle)) throw new Error('mutation target not found')
  return { ...loaded, source: source.replace(needle,
    "['mode', () => true, 'mode:in{text,external}']") }
} })
await import('./packages/dsh-vscode-kit/test/response-contract.test.js')
```
