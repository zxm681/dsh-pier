## 2. 决策表（四.7）逐行落地

实现见 `document-write-policy.js` 的 `judge()`；判序就是语义（先命中者胜）：

`① 已 taint → 拒` → `② 无证据源 → observation-gap` → `③ 干净 → 放行` → `④ deleteFile 脏 → dirty-quarantine` → `⑤ 脏且 grant 无许可 → dirty-quarantine` → `⑥ 脏且所有权未证明 → attribution-unknown` → `⑦ 放行（self-only）`

| # | 规划 4.7 的情形 | 实现结论 | 码 / `reason` | 守着它的用例 |
|---|---|---|---|---|
| 1 | 干净基线、无外部增量 | `applyEdit` 可 / `save` 可（无 CAS）/ `delete` 走原确认+备份+隔离 | — | `决策表第 1 行`、t39 干净保存、t40 归档主用例 |
| 2 | 脏且**已证明**本 grant 连续链（`self-only`/`bridge-correlated`）+ grant 有 dirty 许可 | `applyEdit` 可（仍判双锚点）/ `save` 可（仍判 `expectedDisk` + 最后复核）/ **`delete` 拒** | `-32011 dirty-quarantine`（delete） | `决策表第 2 行`、`★ T62 ③`、t40「授权 + 确有证据 → 归档仍拒」 |
| 3 | 脏且非桥接 / 别的 grant / mixed / unknown | 三者全拒 | `foreign-change` / `mixed-origin` / `attribution-unknown` | `决策表第 3 行`(+补)、`★ T62 ③b`、`★ 重读锚点洗不白` |
| 4 | 曾脏过、后来 `isDirty` 变 false | 仍拒 | 原 `reason` 不变 | `★ isDirty 变 false 不能洗白`、`★ 重读锚点洗不白` 第二段 |
| 5 | 缺观察器 / 账本超限 / 失步 | 三者全拒（**含干净缓冲区**） | `observation-gap` | `老宿主（没有观察器）→ 拒写`、`changeLedger:false 等同没有证据源`、`决策表第 6 行` |
| 6 | 缺基线（基线之前就有别人的字） | 拒 | `dirty-quarantine` | `预先 dirty 的缓冲区 → 拒写` |
| 7 | 实例变更（关闭重开） | 拒 | `attribution-unknown`（`note: incarnation-changed`） | `决策表第 5 行`、policy 单测 |
| 8 | 拿**最新**双锚点重读 | 仍拒（**不是** `-32012`） | `-32011` | `T62 ★ 重读锚点洗不白` |

`-32012`（双锚点/范围前置）与 `-32013`（磁盘态）的既有判定**一条没放宽**：版本不符仍先回 `-32012`（t39/t40 双锚点用例全绿），磁盘不符仍 `-32013`（`host.calls.save === 0`）。`-32011` 只在"锚点都对得上、但内容来源不可判"时出现——这正是为什么消费者对它的处置必须是"别重发"。

### 5.3 假宿主补 `observeTextChanges`（v2 的**语义代价**，14 个文件）

`observation-gap` 是**无条件**拒写（含干净缓冲区）：没有同源观察器就连"干净基线"都建立不了。因此所有**假宿主**必须提供这个口，否则整片写测试会红成"门在正常工作"的样子。补的是 `observeTextChanges: () => ({ dispose() {} })`（**真的实现了、只是永远不报变更**），不是把门关掉。涉及：`apply-edit`、`capabilities`、`document-version`、`edit-attribution`、`edit-transaction`、`t34-incarnation`、`t35-incarnation-mandatory`、`t39-save`、`t40-delete`、`t5-negative-lifecycle`、`compat-gate`、`connector`、`hello-window`、`scripts/e2e.mjs`；真宿主侧对应 `vscode.workspace.onDidChangeTextDocument`（`t46-quarantine-primitive.test.js` 的 `vscode` mock 也补了）。

**这是老宿主的真实代价**：没有 `onDidChangeTextDocument` 的宿主上，本桥接从此**只读**。报告不掩饰：这会让一部分"以前能写"的环境现在写不了，而这是 4.7 明确要求的失败闭合（"看不到别人就当没别人"正是要挡的默认放行）。

## 6. 已知限制与诚实声明

1. **`save` 无 CAS**：⑧b 的最后复核只能**缩小**窗口，不能消灭它——复核之后、`saveDocument` 之内仍有保存参与者与人工交错的可能。观察到这种污染时只能如实报（`postSave.mayHaveApplied: true`）并冻结，**不回滚**。
2. **构造区间的 `isDirty` 是排队时的实测值**：同步区间禁止 `await`，拿不到新鲜脏态。该门的价值是"版本/实例/冻结原因在最后这段没有 await 的窗口里有没有变"，脏内容的最终依据是账本 `dirtyBefore` 与冻结表。代码里有注释（`capabilities.js` 约 1693–1710 行），**不掩饰**。
3. **迟到的自家事件不 taint**：`version <= lastVersion` 直接判 `stale`。这是有意的不对称——否则每个正常 `applyEdit` 都会把自己的文件冻结掉。代价：如果真有"别的写入恰好落在同一个 version"（现实中需要同一实例、同一版本号被复用），本模块看不见；账本那一层的 `desyncs` 会记。
4. **`opts.changeLedger: false` 现在的语义是"只读桥接"**：它不再是兼容出口，而是"我没有证据源"，一律 `-32011 observation-gap`。
5. **键归一化是收紧方向**：`keyOf()` 折大小写 + 折分隔符，只会让更多写法命中同一条冻结状态（多冻结、不少冻结）。
6. **真机验证不在本卡**（规划里 A2 的真机可证清单留给后续）：本卡的四门全部是单测 + 假宿主 E2E，**不能**证明真实 VS Code 上的 `onDidChangeTextDocument` 时机、`formatOnSave` 的实际顺序。
7. `work/t62-patch-kit-compat.py` 是一次性迁移脚本（kit compat-gate 的 v1→v2），跑完即弃；留在 `work/` 作证据。
