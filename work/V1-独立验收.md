## 3. must-fix 清单

### MF-01 — 阻断：save 的失败出口遗留 inflight，外来脏内容能被再次保存

**位置**：[capabilities.js:1912–1954](<../packages/dsh-kit-bridge/src/capabilities.js#L1912-L1954>)，联动[document-write-policy.js:228–232](<../packages/dsh-kit-bridge/src/document-write-policy.js#L228-L232>)、[300–303](<../packages/dsh-kit-bridge/src/document-write-policy.js#L300-L303>)、[455–467](<../packages/dsh-kit-bridge/src/document-write-policy.js#L455-L467>)。

- `beginWrite` 后，只在宿主抛异常的 catch 里及成功路径末端 endWrite。宿主正常返回 `saved:false`、非布尔，或写后路径/文档身份检查抛异常，均绕过收尾。
- 真机 API 可合法返回 false：[宿主:429–445](<../packages/dsh-kit-bridge/src/vscode-host.js#L429-L445>) 原样回传，并非只存在于畸形 mock。
- **本轮实测**：用实际 `createCapabilities` / `GrantStore` / writePolicy，先通过真实 `rebaseBaseline` handler 建人工确认脏基线，grant dirty许可=true；第一次 save 假宿主回 false → `-32603 host-save-failed`，状态仍 `inflight:1, dirtyOwned:true`；随后送一条外来 v2 事件，仍 `taint:null, dirtyOwned:true`。用更新锚点再 save，宿主被调用并返回 `saved:true`。输出见[探针:1–6](<V1-save-failure.log#L1-L6>)。探针没有对真实文档或磁盘写入。
- **后果**：外来事件被永久当作“本端写窗口内”，没有触发 foreign-change；旧的 dirtyOwned 继续授权新的人工/外部内容。它不是 save 无 CAS 的已知窗口，而是一次已结束失败操作留下的跨请求状态泄漏。
- **修法方向**：beginWrite 后用覆盖全部返回/异常分支的 finally 保证恰好一次 endWrite；失败时不能保留未经证明的脏所有权。补 `false`、非布尔、路径复核异常、身份异常四类失败后的外部事件及再次写入回归，验证 inflight=0、来源不可判不得保存。

### MF-02 — 重要且阻断本次契约验收：LRU 淘汰无条件丢 taint，人工交接不再唯一

**位置**：[document-write-policy.js:135–178](<../packages/dsh-kit-bridge/src/document-write-policy.js#L135-L178>)（尤其172–176），对照[契约:1224–1226](<../docs/协作编辑-钩子契约.md#L1224-L1226>)。

- 容量默认512，LRU 删除的是整条文件状态，未区分 tainted、inflight 或普通诊断。之后访问该文件会重建 `taint:null`。
- **本轮实测**：默认 createWritePolicy，先 markForeign A；对干净 A 的 deleteFile 判定为 `allowed:false, reason:'foreign-change'`；再观察512个不同文件；同样输入变为 `allowed:true, attribution:'unknown'`，未调用 establishBaseline。见[输出:1–2](<V1-probes.log#L1-L2>)。
- **后果**：活动其它文件即可自动解除 A 的归档冻结；容量压力不是人工交接，却成为清锁通道。这里只证明写许可门被绕过；没有声称最终归档绕过了它后面仍存在的人工确认/备份门。
- **修法方向**：不能把安全冻结与可丢诊断共用无条件 LRU；保留冻结证据，或在超限/状态遗失时转入显式 fail-closed 的“证据不可用”态，拒绝相关写直到人工确认。inflight 状态同样不可静默淘汰；补超过默认容量的回归，不仅测缩小的测试上限。

## 4. 可延后项与疑问（均明确不阻断）

### D-01 — 不阻断：唯一 unlink 仍是按名采样，不是条件删除

[host:27–36](<../packages/dsh-kit-bridge/src/vscode-host.js#L27-L36>) 在 `await lstat` 与 `await unlink` 间可换名；内存 fs 探针令 lstat 返回 inode1、继续前切为 inode2，实际私有函数仍回 `removed:true`，记录被删 inode2：[探针末行](<V1-probes.log#L7>)。该结果证明采样边界，不是本机用户文件被删的实测。

[既有交付:155–156](<t68-createFile.md#L155-L156>) 已明确排除同用户进程竞态；[路径模块:28–39](<../packages/dsh-kit-bridge/src/workspace-paths.js#L28-L39>) 也明示这一威胁边界。因此本报告不把已声明排除的对手重新算入 must-fix，也不承诺“只要有dev/ino检查就绝不可能删替换物”。若未来要覆盖该对手，应改为不销毁残件/归档或真正可证明身份的原语，不能只加一次路径采样。

### D-02 — 不阻断：全仓删除面说法、当前文档入口需收口
