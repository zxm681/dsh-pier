## 一、阻断项

### B1 / blocker：快照与删除没有绑定同一个文件对象，末端替换可静默删错文件

**位置**：[capabilities.js:1565–1596](<../packages/dsh-kit-bridge/src/capabilities.js#L1565-L1596>)、[vscode-host.js:521–525](<../packages/dsh-kit-bridge/src/vscode-host.js#L521-L525>)。

**问题与结论**：确认后确实重新验路径、stat、sha256，但最后一次 `await readSnapshotBytes(...)` 读完与 `workspace.fs.delete(uri,...)` 实际按路径执行之间，没有对象身份/CAS 绑定。快照比对通过，只能证明读到的旧字节一致，不能证明接下来按这个名字删除的还是它。替换后仍返回 `deleted:true`，快照是旧文件的；新文件既没被人看过，也没被交出恢复材料。

**实证 1：能力层最后一次快照返回前交错替换**。第一次读旧内容并确认；第二次读取得到旧 Buffer 后，把目标 rename 到 `.old`，在原名写入另一文件，随后让 read Promise 返回：

```text
DELETE_BYTES after-final-snapshot-replace "VICTIM-with-no-snapshot\n"
exists:false, deletes:1, reads:2
result.deleted:true
result.snapshotText:"ORIGINAL-secret\n"
```

见 [探针输出:4–5](<t41-probes.log#L4-L5>)。

**实证 2：原适配器贯通到 provider 破坏点**。不修改真实适配器，让模拟 `workspace.fs.delete` 在消费 URI 时完成相同替换再实际 unlink 临时文件：

```text
mode:"provider-race"
result.deleted:true
result.snapshot.text:"RECOVERY_SECRET"
deletedBytes:"NEW VICTIM NO BACKUP"
exists:false
```

见 [原适配器输出:2](<t41-host-probes.log#L2>)。这证明即使再补一次同步 stat，provider 的异步按路径删除仍无对象绑定；不是“漏加一次比较”这么简单。

**为什么阻断**：这是新增不可逆能力对**未被确认的文件版本**静默执行删除并报成功，满足“未授权写入成功/不可逆操作可被静默触发”的标准；不是把已经确认的文件删掉后如实报告 `trashed:unknown`。同用户恶意 reparse 替换的历史排除，不能证明正常外部工具原子替换文件时不会丢失新内容。[契约 §6.2.6](<../docs/协作编辑-钩子契约.md#L639-L651>) 对 `save()` 的无 CAS 免责，不等于批准删除未确认、无恢复材料的其他字节。

**修改建议**：在能够证明“确认对象 = 快照对象 = 删除对象”前，不对外开放该删除能力。需要对象绑定/事务式隔离方案及竞争回归测试；若 VS Code 的路径式 API 无法提供此保证，应改产品能力或提交独立契约裁决，不能用再一次 stat/hash 冒充原子保证。至少新增上述两个窗口的失败测试，要求替换文件保留且不得报成功。本评审不实现修复。

## 二、重要项（不扩大阻断标准）

### I1 / important：超过 1 MiB 的文本和非 UTF-8 文件删除后，实际没有交出恢复材料

**位置**：[capabilities.js:74–120](<../packages/dsh-kit-bridge/src/capabilities.js#L74-L120>)、[response-contract.js:218–270](<../packages/dsh-vscode-kit/src/response-contract.js#L218-L270>)。

**结论**：1,048,577 字节文本删除成功，返回 `textOmitted:'too-large'`；4 字节非 UTF-8 文件删除成功，仅返回 sha256/长度/encoding。内容只在执行中读过，没有持久化备份，也没有交给调用方。**hash 不能恢复原字节**；代码注释“材料仍以 sha256 形式在”把身份校验材料误当恢复材料，违反 [契约 §6.2.4 第三条](<../docs/协作编辑-钩子契约.md#L570-L576>)。

**证据**：[探针输出:8–11](<t41-probes.log#L8-L11>)。两个场景均 `exists:false,deletes:1`，`snapshotKeys` 无正文/字节载荷。

**建议**：在确认前拒绝无法完整交付备份的内容，或提供有生命周期/访问控制的无损二进制快照载体并验证可恢复；响应合同不应把可恢复数据的缺失当普通成功。按本任务限定阻断标准，这两例有人明确确认，未实证越权/静默触发/DoS，**单列重要项、不另升阻断**。

### I2 / important：未知方法兜底对 Object.prototype 成员失效

**位置**：[whitelist.js:103–105](<../packages/dsh-vscode-kit/src/whitelist.js#L103-L105>)、[whitelist.js:249–251](<../packages/dsh-vscode-kit/src/whitelist.js#L249-L251>)。

**结论**：`METHOD_TIERS[method]` 会读原型；`toString`、`constructor`、`__proto__` 得到函数/对象而非 `'delete'`，`tierRank` 返回 -1，随后 `-1 <= 0` 让 read 消费者通过白名单。探针三者均发出了请求，违背“未知方法 fail-closed”。

**证据**：[探针输出:33–35](<t41-probes.log#L33-L35>)。未证明这些名字可以映射到实际写方法，**不是已实证写提权，不阻断**。

**建议**：用 `Object.hasOwn(METHOD_TIERS, method)` 或无原型 Map/对象查表，并在比较前明确拒非法 tier；增加原型成员测试。

## 三、六项必验逐项裁决

### 1. 能不能提权？——固定 read facade 不能靠 opts/params 改身份；匿名 facade 可自报另一个获准身份

**结论**：有边界，不能笼统称“不能提权”。

- 匿名 facade 的 `forPlugin` **真的绑定新身份**，不是 no-op：[index.js:1701](<../packages/dsh-vscode-kit/src/index.js#L1701>)。已有 bound facade 的 `forPlugin` 才返回自身：[index.js:413–415](<../packages/dsh-vscode-kit/src/index.js#L413-L415>)；探针 `BOUND_REBIND_SAME true`。
- `opts.consumer`、`params.consumer` 都不能覆盖入口闭包身份；对三种写方法全部 `-32602 consumer-unbound`，没有发包。身份由第四实参传入：[index.js:359–365](<../packages/dsh-vscode-kit/src/index.js#L359-L365>)、[index.js:1326–1332](<../packages/dsh-vscode-kit/src/index.js#L1326-L1332>)。
- `declared × allowed × method` **64 格真值表全部符合 min，0 failures**。reader 配 read、声明 delete 的三种写请求全拒；大小写变化 `vscode.Save` / `VSCODE.save` 也拒。
- 普通未知 `vscode.future` 按 delete 拒。原型成员例外见 I2。
- `bridge.*` 前缀免白名单：[index.js:633–635](<../packages/dsh-vscode-kit/src/index.js#L633-L635>)；`bridge.vscode.save` 确实发出，但真实下游没有把该名字重写成 `vscode.save`，不构成已证实业务写旁路。`bridge.grant/Revoke` 是授权控制面，不能把“协商豁免”宣传成隔离控制面；下游处理见 [connector.js:119–148](<../packages/dsh-kit-bridge/src/connector.js#L119-L148>)。
- **自报身份限制**：持有匿名 facade 的只读调用方可以 `forPlugin('writer',{declared:'delete'})`，只要配置里 writer 获准，就能越过白名单；探针三种写均 `SENT`。这部分是模拟 link 回执，证明**门被越过/帧发出**，不冒充本探针已完成真实未授权落盘。
- [whitelist.js:23–41](<../packages/dsh-vscode-kit/src/whitelist.js#L23-L41>)、[whitelist.js:345–348](<../packages/dsh-vscode-kit/src/whitelist.js#L345-L348>) **明确自认 advisory、身份自报、不防恶意同进程插件**。因此不能把它当宿主认证/进程沙箱；正常固定入口的 T-A 误调用被收口，T-B 仍需确认+完整快照，T-C 只有自报身份的诊断归因。

**证据**：[完整身份与档位输出:13–37](<t41-probes.log#L13-L37>)。

**是否阻断**：固定 read 入口覆盖失败；自报身份绕过是已声明机制边界，在本轮不单列恶意同进程攻击阻断。若产品要求“即使持有匿名入口也不可冒名”，目前做不到，须由宿主提供可信身份后再称授权边界。

**文档是否写清**：写清了。[契约 Tier 3 不保证项](<../docs/协作编辑-钩子契约.md#L481>)、[§6.2.3](<../docs/协作编辑-钩子契约.md#L527-L552>)、[§6.2.6](<../docs/协作编辑-钩子契约.md#L645-L650>) 都明确无 CAS、善意早失败、不保证覆盖窗口内的外部改动；实现注释 [capabilities.js:1217–1225](<../packages/dsh-kit-bridge/src/capabilities.js#L1217-L1225>) 同样诚实。

### 3. 删除三个 TOCTOU 窗口——确认期间两种变更挡住，最终窗口删错文件

实际顺序不是任务里假定的“确认后首次读快照”，而是：**预验磁盘 → 首次快照 → 确认 → 路径重验 → 再验磁盘 → 再读快照比 hash → 删除**。见 [capabilities.js:1544–1596](<../packages/dsh-kit-bridge/src/capabilities.js#L1544-L1596>)。

| 窗口 | 实证结果 | 证据 | 阻断 |
|---|---|---|---|
| ① 确认期间 rename 旧文件、原名放另一文件 | `-32013`，替换文件仍在，delete=0 | [输出:2](<t41-probes.log#L2>) | 否 |
| ② 确认期间修改内容 | `-32013`，新内容仍在，delete=0 | [输出:3](<t41-probes.log#L3>) | 否 |
| ② 加强：修改为同 size 并精确保留 mtime | 二次读发现 `reason:'bytes-changed'`，delete=0 | [输出:12](<t41-probes.log#L12>) | 否 |
| ③ 最后一次快照读完至真实删除之间替换 | 返回成功，实际删掉另一份字节；快照无法恢复它 | [能力输出:4–5](<t41-probes.log#L4-L5>) / [适配器输出:2](<t41-host-probes.log#L2>) | **是，B1** |

**判据裁决**：不允许删错人的文件；不能用确认过同一路径解释确认过未来任意替换内容。普通工具的原子保存也会换 inode，不必预设恶意攻击者。
