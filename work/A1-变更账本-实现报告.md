## 2. 设计：三层证据，缺一层就降级

账本不判许可，它是**证据层**。判定所需的三段证据分别在不同时刻取：

| 阶段 | 位置 | 取到什么 |
| --- | --- | --- |
| ① `begin` | `capabilities.js` 能力层，绑定门与路径重验**之后**、写宿主**之前** | 自签 `operationId`、grant 身份（按 id 回查授权表）、预期 `edits`（0-based `character` 口径）、`expectedVersion` / `expectedIncarnation` / `dirty` |
| ② `construct` | `edit-transaction.js` `applyEditAtomically` 的**同步区间**内、`apply(builder)` 之前 | before 基准：`version` / `incarnation` / `text`(→`hash`) / `textLength`；以及 `constructed=true` |
| ③ `settle` | 能力层写后**重新实测** `readDocumentState(includeText:true)` | after 锚点（version / incarnation / hash / textLength / dirty）+ 事件环形缓冲里的实际事件 |

为什么 ② 必须在同步区间：before 那份坐标所基于的那个版本，只有"构造 edit 的同一个同步区间"里读到的才算数。放到事务外（哪怕只早一个 `await`）就可能读到另一版快照，于是 after 与预期的比对、事件链的版本衔接一起判错——那正好会把我跟别人判反。

观察者是**证据，不是闸**：`observe` 抛异常被事务吞掉并记日志（`constructed` 已置位，此处再抛会把一次本来成功的写入变成失败，那是最糟的失败形态）。

### 2.1 事件源

`vscode-host.js` 新增 `observeTextChanges(handler)`，直接订阅 `vscode.workspace.onDidChangeTextDocument`，**不复用** `editorEvents` 推流链。理由：推流是"按订阅策略发不发"，没有订阅者时一个字节都不发；归属判定要的是本地事实，接在推流链上等于让"没人订阅"变成"看不出谁改的"，那正是要避免的未知态。

归一化一次做完，交给账本的形状：`{file, version, incarnation, changes[{start{line,character},end,text}], reasonCode}`。`incarnation` 用**同一个** `incarnationOf`——读侧 `readDocumentState`、写侧事务、事件侧三处口径同源，这是归属能成立的前提。

### 2.2 判定阶梯（`decide()`，顺序即优先级）

不利结论先出，任何一条命中就不再往下走：

| 命中条件 | 结论 / reason |
| --- | --- |
| `record.deny`（开记录时已被拒） | `unknown`（记具体原因） |
| 观察器未 `attached`（宿主没这条 API / 装失败） | `unknown` `observer-unavailable` |
| 记录窗口内有链失步（`desyncSeq`） | `unknown` `event-gap` |
| 事件环形缓冲溢出过（`dropped`） | `unknown` `ledger-event-dropped` |
| 没有 before 基准 | `unknown` `no-baseline` |
| before 文本超上限（1 MiB） | `unknown` `text-too-large` |
| **写前已 dirty** | `unknown` `pre-dirty` |
| `outcome !== 'applied'` | `unknown` `host-timeout` / `host-error` / `host-rejected(-with-other-changes)` |
| after 实测失败或缺文本 | `unknown` `after-unmeasured` / `after-text-unavailable` |
| **after 化身 ≠ before 化身** | `unknown` `incarnation-changed` |
| no-op（builder 无实际改动） | `unknown` `no-op` |
| 有**不匹配**的事件 | `mixed` `other-window-incarnation`（另一化身）/ `mixed` `extra-changes` |
| 内容 ≠ 预期：文本没变 | `unknown` `write-not-visible` |
| 内容 ≠ 预期：文本变了 | `mixed` `after-content-differs` |
| 内容逐字相符、**0 条事件**（事件晚于 Promise） | `self-only` `event-chain-pending` |
| 内容逐字相符、恰好 1 条且匹配（事件早于 Promise） | **`bridge-correlated`** `event-chain-matched` |
| 内容逐字相符、事件条数/内容对不上 | `self-only` `event-chain-unverifiable` |

`bridge-correlated` 的唯一通路就是最后那条：**宿主报接受** + **事件链匹配** + **after 实测逐字等于预期** + **没有插入的额外变化**。四条同时成立才给，任一缺失就退回 `self-only` / `mixed` / `unknown`。

### 2.3 不采信入参自报

- `operationId` 由账本 `begin` 签发；`params.operationId` / `params.source` / `params.attribution` **一律不读**。
- `params.grant` 是调用方自己填的，不能自证：`grantIdentityFor()` 按 `id` 回查 `grants.lookup()`，记下**查到的** `sessionId` / `epoch`，查不到就 `resolved:false`（声明值只当日志线索，不进判据）。

归属摘要必含 `before` / `after` 两个锚点（`version` / `incarnation` / `hash` / `textLength` / `dirty`）+ `attribution` + `attributionReason`；**after 一律实测**（专门有一条测试：写后有人又改一次 → `mixed after-content-differs`，且断言回执里的 `after.hash` 等于**实测**文本的 hash，不等于期望文本的 hash——"不许回显期望值"）。

## 4. 实现过程中修掉的两个**会反过来伤到本卡判据**的设计错误

写第一版时这两处都"看起来没问题"，是负例把它们逼出来的，记在这里因为它们正是本卡最怕的失败形态：

1. **把"每一条额外事件的 version ≠ before+1"当跳号**。我这一笔是 v6，人再敲一下就是 v7——那不是"漏了事件"，那是**额外的正常变化**。按旧判据会把它误报成 `unknown event-gap`，把有用的 `mixed extra-changes` 丢掉，等于**看不到人工交错**。已改为：失步只由观察侧自己按链连续性记（`observeChange` → `desyncSeq` → `event-gap`），两处各判一套是错的。
2. **只把 `observerAtBegin === 'unavailable'` 当"看不见"**，`unattached`（宿主没这条 API、事件源根本没装上）漏了过去 → 一条"观察器缺失"的负例当时报了 `bridge-correlated`。已改为 `observerAtBegin !== 'attached'` 一律 `unknown observer-unavailable`：看不见不等于没有。

另有一处是**测试替身自己的错**，也记下来免得后人重踩：假宿主的事件里只回 `column` 口径，而 VS Code 的 `contentChanges[].range` 用 `character`——不归一就会让"逐条比对"永远对不上，把 `extra-changes` 假阳性出来。假宿主现在两种列名都认。

## 6. 与规划 / 合同的差异、风险与遗留

1. **`response-contract.js` 能容纳新字段，未破坏旧消费者**：归属字段整组 **optional**（老扩展不返回这几个键 → 仍是合法响应，不会变 `-32009`）；但"给了"就走类型谓词，且加了一条 `consistency`：`attribution` 一旦出现就**必须**同时有 `operationId` + `before` + `after`——只发结论不发证据的回执视为畸形。既有四个字段（`applied` / `file` / `saved===false` / `textLength`）语义与必填性未动。
2. **`ATTRIBUTION_VALUES` 在 kit 与 bridge 各抄了一份字面量**（kit 是零依赖协议库，铁律 3 禁止反向往 bridge import）。防漂移靠 `test/change-ledger.test.js` 里的静态比对（读 `response-contract.js` 源码对账）。**这是有意的重复，不是遗漏**。
3. **观察器缺失 = 永不给 `bridge-correlated`**：生产上 `vscode.workspace.onDidChangeTextDocument` 一定存在，所以这是老宿主/替身的降级路径；代价是这些环境下回执恒为 `unknown`。这是"保留未知态"的直接后果，不是缺陷。
4. **事件环形缓冲按每文件 32 条、账本 64 条记录、before 文本 1 MiB 封顶**：超限一律降级 `unknown`（`ledger-event-dropped` / `text-too-large`），不做静默淘汰后的"猜"。
5. **`opts.changeLedger === false` 可整块关掉**（诊断/极端降级用）：关掉后回执不带归属字段，形状回到 T61 之前。
6. **未做**（明确不在本卡范围）：归属信息不进事件推流（只进 applyEdit 回执）；P2 的"跨会话归属广播"没有实现，也没留下半成品。
