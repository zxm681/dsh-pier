# 协作编辑需求草案（独立新阶段）

> 状态：**需求草案，非实现；待技术评审**。本文件记录已确认的人机协作意图与可验证行为，不声明现有桥接协议、VS Code 扩展或 DSH Web GUI 已支持这些能力，也不指定既有 API 或已裁决的实现方案。
> 边界：[`phase2-需求文档.md`](./phase2-需求文档.md) §4.2 将注入/编辑能力排除在**原打样范围**之外；本草案属于后续独立阶段，不追溯修改原打样结论。项目 `AGENTS.md` 的现行约定仍有效；下述会话授权等是未来需求意图，尚待设计与审查，不构成对现行约定的暗中豁免。

## 一、已确认意图

1. **授权及作用域**：仅在当前**受信任**的 VS Code 工作区内，由人授予会话级、连续的自动编辑权限，并可随时撤销；权限覆盖文本编辑与新建、删除、重命名，越出工作区不可操作。授权不是对提交、推送、合并或提高删除权限档位的授权。
2. **可见、可介入的编辑**：编辑期间人可随时查看差异、主动介入，不要求为了看差异强制暂停 DSH。文本编辑期允许未保存状态；新建、删除、重命名立即改变磁盘，须受权限和删除确认规则约束。
3. **双分支与双工作树**：即使人和 DSH 修改不同模块，也各用独立的本地 Git 分支与 worktree。人的原 VS Code 窗口不切分支，DSH 不抢焦点。DSH Web GUI 侧边栏实时显示进度与差异摘要；人主动请求完整差异时，才按需打开指向 DSH worktree 的第二个 VS Code 窗口，不把该窗口作为持续展示的前提。
4. **人介入 DSH 工作树**：人可直接手动修改 DSH 工作树中的文件。DSH 保留该修改，及时分析其可能动机、合理性、潜在错误及对当前工作的帮助，并标注人工/DSH 改动归属；不得覆盖该人工修改，也不得自动保存或提交**该文件**。DSH 提供纠错建议或差异，等待人确认；不受影响的其他文件可继续工作。归属不明时不得将改动擅自归为 DSH 自有。
5. **保存与验证边界**：文本编辑期间允许未保存；进行磁盘测试或 DSH 的临时本地提交检查点前，DSH 仅可自动保存**由自己独立修改**的文本。磁盘测试不能把未保存内容说成已验证；涉及人工修改或混合归属的文件，不得借测试/检查点自动保存或提交，须待人处理并明确验证对象。新建、删除、重命名因即时落盘，必须单独受相应权限约束。
6. **提交与集成权责**：人自行保存，并在人的分支上自行本地提交；DSH 仅在自己分支通过 commit 前不可豁免检查后，才可作临时本地提交。DSH 不替人提交、不推送、不擅自合入主分支。在**独立临时工作树**审查双方**已提交**的差异，并预演集成、接口影响、冲突及潜在 bug；出现真实 Git 冲突时先提出方案和差异，待人确认后**仅在临时工作树**应用。最终合并及提交由人决定。未保存或未提交改动不因预演而被视为已纳入集成。
7. **删除权限**：默认每次删除均需人确认。只有人在本项目、本会话中主动**逐级**调高删除档位后，普通删除才可按所选档位免逐次确认；DSH 不能自行调高。删除涉及未提交、未保存或 Git 未跟踪内容时，**无论档位**均须列明路径并逐次确认。不存在永久的“达到 3 个文件就确认”阈值；不另设独立备份区，Git/VS Code 撤销也不能承诺可靠恢复。若无法判明是否属上述高风险内容，不能据此放宽确认。

## 二、可验证行为场景（供后续方案验收，不代表现已通过）

| 场景 | 期望观察结果 |
|---|---|
| 未受信任工作区、未授权或会话授权被撤销后尝试编辑/新建/删除/重命名 | 工作区内也不得继续自动操作；工作区外路径始终被拒绝，已有授权不外溢。 |
| 人保持原窗口在人的分支，DSH 编辑不同模块 | 两边分支和 worktree 隔离；原窗口不切分支、不被抢焦点；侧栏可见实时进度、差异摘要；未主动点完整差异则不打开第二窗口。 |
| 人在编辑中点看完整差异并介入 | 按需打开 DSH worktree 第二窗口；人随时能看差异和介入，不因查看被强制暂停 DSH。 |
| 人直接修改 DSH 工作树某文件，DSH 同时还有别的待办 | 人工修改原样保留并标注归属，DSH 给出动机/合理性/风险/帮助分析及待确认建议；该文件不被 DSH 覆盖、自动保存或提交，其他文件可继续。 |
| 编辑器有未保存文本，发起磁盘测试或临时提交检查点 | 只自动保存 DSH 独立修改文本；人工/混合归属文件不自动保存或提交。测试报告明确磁盘版本与未保存版本的区别，不声称未保存文本通过测试。 |
| 新建、删除或重命名 | 操作按权限即时反映到磁盘；默认删除逐次确认。人在本会话逐级升档后，仅符合档位的普通删除可免逐次确认。 |
| 删除含未提交、未保存或未跟踪内容，或请求工作区外路径 | 前者即使升档仍列路径逐次确认；后者不可操作；不作可靠恢复承诺。 |
| 双方各自提交后预演集成，遇到真实冲突 | 独立临时工作树展示已提交差异、接口影响与冲突方案；未经人确认不应用冲突方案，确认后也只在临时工作树应用；不自动合并、推送或替人提交。 |

## 三、待技术评审：未决事项与风险

- **侧栏和跨进程工作树可行性**：核实 DSH Web GUI 实时进度/差异摘要、按需完整差异及第二 VS Code 窗口的可用边界；验证两个窗口/多个连接的路由、焦点与关闭行为，不假定现有接口已经具备。跨进程通信及安全边界须按项目 `AGENTS.md` 先查成熟项目源码先例，再定设计。
- **授权撤销与删除范围安全**：定义会话、工作区信任变化、撤销时在途操作、路径归一化/符号链接/重命名越界的判定；设计删除档位、逐级升档的人为操作与状态回退、普通与高风险删除识别及失败时的保守行为。未保存内容能否被删除判定识别仍需验证；无可靠恢复保证会放大误删风险。
- **人工/DSH 改动与保存提交归属**：验证同一文件、同一缓冲区的交错改动能否可靠区分；定义归属不明时的停写/待确认状态、人工介入的通知与误覆盖防护，以及 DSH 自有独立修改的保存和暂存边界。不能把文件路径归属等同于实际改动归属。
- **未保存内容可见性与集成条件**：核实缓冲区与磁盘差异可见性、差异摘要的一致性与时效；明确测试对应的磁盘快照、双方已提交内容进入临时预演的条件，以及未保存/未提交内容不参与预演时如何提示。需验证冲突展示和人工确认后仅临时应用的可操作性。
- **验证计划**：评审后再确定可实施方案及安全/并发/权限测试，覆盖撤销竞争、路径逃逸、人工与自动交错、未保存/未跟踪删除、磁盘测试误报、窗口焦点及临时工作树隔离；不能把此表场景当作已有测试结果。

## 四、范围外与本草案限制

- 本文不创建分支、worktree、提交、合并或推送；不修改代码、原 phase2 文档或项目 `AGENTS.md`，也不宣布任何功能已实现。
- 不替人保存/提交人的分支，不自动处理冲突或最终合并；不保证 Git/VS Code 撤销可恢复、不新增独立备份区。
- 不预先指定 API、协议字段、侧栏实现机制或删除升档的具体级数/阈值；这些必须经技术评审和用户进一步确认后设计。
- 本需求只讨论当前受信任的 VS Code 工作区；工作区外写入、推送远端及未经授权的权限升级均不在范围内。
