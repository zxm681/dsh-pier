# 多窗口寻址设计（指定/切换目标 VS Code 窗口）

> 状态：设计与实施验收记录（T54 更新：多窗口实现已落地，A10–A13 已真机确证；历史设计条款不等于全部验收通过）
> 当前实现以[契约 §3.1](<协作编辑-钩子契约.md#31-多窗口发现与读路径寻址t52按未提交实现核实>)为准；本文 §7 记录本轮真实验证边界，§9 保留未覆盖项。
> 目标：让调用方能说「往 2 号窗口打开文件」，同时**不削弱**写入绑定门（契约 §6.1.1）。
> 标注约定：`[码]` 有源码行号、`[文档]` 有既有文档依据、`[待核]` 是未核实结论（附所需证据）。

## 0. 结论摘要

1. **一条连接 = 一个窗口**：扩展在窗口进程里 `activate()` 并各建一条连接 `[码] packages/dsh-kit-bridge/src/extension.js:485-504`（`[实测]` VS Code 1.143.1 两个真实窗口分别注册为 win-08 / win-09，stable:true；证据与范围见 §7）。
2. **`windowId` 由 DSH 侧签发**，不从 VS Code 取（扩展 API 拿不到稳定窗口身份，见 §1）；`connSeq` 是连接先后，两者**分字段、分来源、禁止互相比**。
3. **能力面**：新增 `vscode.windows.list()`（只读、可发现）+ `request(m, p, {target})` 仅用于**读**；写路径带 `target` **一律拒**。
4. 新错误码从 **`-32014`** 起 `[码] packages/dsh-vscode-kit/src/protocol.js`；`-32012/-32013` 仍是文档版本 / 磁盘真值冲突；**`-32011` 已启用为 `document-dirty`**（`[码] packages/dsh-vscode-kit/src/protocol.js:78`，A2/T62 脏态门），不再是空号。
5. `broadcast` 语义**不变**；不引入"定向广播"。

### 1.1 候选身份源（逐个核过）

| 候选 | 出处 | 能区分「同工作区两窗口」 | 跨重启 | 扩展能拿到 | 结论 |

`env.sessionId` 的实现链：扩展侧 `vscode.env.sessionId` → `initData.telemetryInfo.sessionId` `[码] src/vs/workbench/api/common/extHost.api.impl.ts:430`。
**已证结论（本次双窗口）**：两个真实窗口的 sessionId 不同，如 `593cf5f1-…` 与 `f8b4c99a-…`；
[运行态注册表](<C:/Users/zxm/.dsh/dsh-vscode-kit/windows.json>) 的 win-01 / win-02 指纹保留该采样（2026-10-23）。
据此可用独立指纹区分本次两个窗口；A11 又证实保持 VS Code 会话时，DSH 重启后仍复用 win-08 / win-09，lastSeenAt 刷新。
A10/A12/A13 的探针证据见[采样文件](<D:/code-workspace/work/multiwin-probe.json>)与 §7；A11 重启过程及 sessionId 比对由用户提供已确证记录，探针本身不含重启事件标记。
这不是所有版本、同工作区双窗或 VS Code 重启后 sessionId 不变的证明。

**勘误（2026-10-25 实查，推翻"指纹命中就复用 windowId"这个前提）**：`env.sessionId` 不是一个稳定 UUID，
而是 **36 字符 UUID + 13 位毫秒时间戳**（`593cf5f1-0756-489e-8cd5-d8a94e17945d` + `1792778886988`），
每次开窗都是新值 `[实测]`。证据：[运行态注册表](<C:/Users/zxm/.dsh/dsh-vscode-kit/windows.json>) 现有 18 条记录，
`sessionId` 18 个互不相同、全部匹配 `[0-9a-f-]{36}\d{13}`；同一个工作区根被签发过多个号——
`D:/code-workspace/work` 8 个（win-02 / 04 / 06 / 07 / 08 / 16 / 17 / 18），
`D:/code-workspace/projects/dsh-vscode-dev` 5 个（win-01 / 03 / 05 / 09 / 15）。
结论：**指纹每次开窗都变 ⇒ 每次签发新 `win-NN`**，`windowId` 不能跨 VS Code 重启复用（§1.3「关窗再开」据此改为"变"）。
A11 那条"DSH 重启复用 win-08 / win-09"仍然成立，但它的前提是 **VS Code 会话没换**（同窗口内重连），与"关窗重开"是两件事。
注册表也不会因此无限膨胀：上限 64 条（`[码] packages/dsh-vscode-kit/src/windows.js:40`），超出按 `lastSeenAt` 淘汰最旧（`[码] packages/dsh-vscode-kit/src/windows.js:286-290`，`_prune()` 排序后 `slice` 保留最近 64 条）。

### 1.2 定义

```text
windowId : DSH 签发的稳定别名，形如 "win-01"。持久化在 ~/.dsh/dsh-vscode-kit/windows.json。
           来源 = 建连时按「指纹」匹配已有条目；匹配不到发新号。
           用途 = 人读 + 读路径路由提示。**不是安全判据**（沿用契约 §6.1.1 既有结论 [文档]）。
connSeq  : server.js 进程内自增的连接序号 [码] server.js:148/203。
           用途 = 排序、"新连接覆盖旧连接"、诊断。**不是身份**。
```

`target` 只接受 `windowId`（`win-01`）或 `connSeq`（`#3`）两种写法，**解析到同一条 link 后仍各自保留原字段**；实现里禁止写 `windowId = String(connSeq)` 这类赋值——那正是 R3 踩过的坑（把连接序当身份）`[文档] 契约 §6.1.1 禁令①`。

### 1.3 稳定性矩阵

| 场景 | `connSeq` | `windowId` | 说明 |
|---|---|---|---|
| 同窗口内扩展重载 | 变（新连接） | **不变**（指纹命中） | 指纹 = `env.sessionId + workspace 根 + uiKind` |
| 关窗再开（同工作区） | 变 | **变**：`sessionId` 含毫秒时间戳，每次开窗都不同 ⇒ 每次新号（实测见 §1.1 末段） | 消费方**不许**持久化 `windowId` —— 它只在本窗口生命周期内有效 |
| 同工作区两窗口并存 | 两个不同值 | 预期指纹不同则两个不同值；同指纹冲突仍需另验 | 本次实测为两个不同工作区，不外推 |
| DSH 重启 | 从 1 重来 | **已真机证实**从文件复用 win-08 / win-09（A11） | 保持 VS Code 会话；`connSeq` **绝不**可跨会话比较 |
| 老扩展（无任何上报） | 有 | 签发 `tmp-<connSeq>`，`stable:false` | 降级，见 §6 |

**降级原则**：身份越弱，`stable` 字段越假，但 `windowId` 字段**永远存在且永不为 null**（铁律 2：方法/字段必须稳定存在）；不稳的信息只能藏在 `stable:false` 里，不许让调用方去判 null。

## 2. 能力面

### 2.1 两方案代价

| | A. `vscode.windows.list()` | B. 请求级 `target` |
|---|---|---|
| 调用方视角 | 先发现再指认（两步） | 一步到位 |
| 泄漏面 | 只露窗口元数据（无 port/token/link） | 露出"连接/窗口"概念，与契约 §7 #1 记录的顾虑一致 `[文档]` |
| 失败可解释性 | 强（能列出有哪些） | 弱（只能报"没这个号"） |
| 实现成本 | 新增 1 能力 + 白名单 1 行档位 + 两侧单测 | 改 `request()` 选目标分支（写/读各一条） |
| 对老扩展 | 当前实现为本端同步发现，不依赖对端能力位；旧稿的 `-32005` 预判不适用（见契约 §3.1） | **可用**（编号由 DSH 生成，不依赖扩展） |
| 削弱绑定门 | 无（纯读） | 有风险，必须限定读路径 |

### 2.2 推荐（只给一个）

> **A 必做（发现面）+ B 仅读路径、`target` 放 `opts`（第 3 实参），不放 `params` 顶层，也不另开方法。**

理由：
- `opts` 现有语义就是"这趟怎么发"（`waitForEditor` / `waitMs` / `sessionId`）`[码] index.js:1342-1348`；`params` 是业务载荷，且已有一条"会话身份不许由线路数据自证"的门（`rejectParamsSessionId`）`[码] index.js:1340`——把 `target` 塞进 `params` 会让这两类东西混在一起。
- 不另开方法：8 个能力 ×（列表 + 各带 target 的变体）会翻倍 API 面，而 `opts` 天然正交。

`vscode.windows.list()` 返回（按 `connSeq` **升序**，唯一排序口径）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `windowId` | string | `win-01` / `tmp-3` |
| `stable` | boolean | `windowId` 是否跨重连稳定 |
| `connSeq` | number | 连接序（仅本次 DSH 进程内可比） |
| `label` | string | 人读名：`<workspace.name 或文件夹名> · <windowId>`（拿不到窗口标题，见 §1.1） |
| `workspace` | `{name, folders[]}` \| null | 来自扩展上报 |
| `uiKind` / `remoteName` | string \| null | 同上 |
| `focused` | boolean \| null | 扩展上报 `window.state.focused` `[码] vscode.d.ts:11038-11043`，明确标注"可能滞后" |
| `extensionVersion` / `protocolVersion` | string \| null | 来自 `bridge.hello` `[码] connector.js:150-163` |
| `active` | boolean | 是否为当前 `_activeLink()` 选中的那条（**只是视图**，`[码] index.js:749-767`） |

## 3. 路由规则

### 3.1 读路径（可被 target 影响）

| 序 | 判定 | 命中动作 |
|---|---|---|
| 1 | `_assertConsumer(consumer, method)` | 不通过 → `-32602` + `data.reason`（现状）`[码] index.js:1336` |
| 2 | `opts.target` 有值 → 解析 | 见 §5 判定表，失败抛 `-32014` |
| 3 | 该方法是 `SESSION_BOUND_READS` 且给了 `sessionId` | 取 grant 记录的 link；**若同时给了 target 且与记录 link 不是同一对象 → `-32014 target-unauthorized`**（拒，不静默忽略）`[码] index.js:1358-1369` |
| 4 | 有合法 target | 用 target 那条 link（**必须是 `trusted` 里的活连接**） |
| 5 | 都没有 | `_waitForEditor()` → `_activeLink()`，无则 `-32007` `[码] index.js:1371-1378` |

### 3.2 写路径（target 一律不参与）

| 序 | 判定 | 结果 |
|---|---|---|
| 1 | `_assertConsumer` | 同上 |
| 2 | **`opts.target` 存在** | **立即 `-32014` / `reason:'target-not-routable'`**，判定位置在 `_bindWriteTarget` **之前** |
| 3 | 目标 = `_bindWriteTarget(params, sessionId)`（grant 记录）| 现状不变 `[码] index.js:1355` |
| 4 | `_writeGate(method, wireParams, link, {sessionId})` | 现状不变 `[码] index.js:1401` |

**冲突处理结论：拒，不忽略。** 理由：忽略等于"答应了但没做"，调用方会以为写进了 2 号窗口而实际写进了 1 号——这类静默偏差比直接报错危险得多；且"比较后放行"会让人误以为写路径支持 target，下次就有人去掉校验。

写路径**为什么不支持 target**：绑定门要求写目标由 grant 记录决定 `[文档] 契约 §6.1.1`、`[码] index.js:1355`。允许 target 选写目标 = 把"授权给谁"退化成"调用方说给谁"。

## 4. 安全判定

| 问题 | 结论 | 依据 |
|---|---|---|
| 谁能指定窗口 | 通过 `_assertConsumer` 的消费者；target **不提升任何权限**——读仍受档位（未登记方法 fail-closed 到最高档 `[码] src/whitelist.js:75-90`），写仍受 Tier 3/4 + grant | `[码] index.js:1336`、`[码] whitelist.js` |
| 未准入连接能否收到窗口清单 | **不能**。`list()` 数据源 = `server.trusted`；`target` 也只解析 `trusted` 成员 | `[码] server.js:137`、`[码] index.js:749-767` |
| 未准入连接能否被 target 命中 | **不能**（同上）；解析失败与"不存在"同码，不泄露"它其实是连着的只是没准入" | 同上 |
| 跨工作区指向 | **读允许、写必然失败**：读只是拿到另一窗口的只读信息；写要跨工作区必须先 grant 到那个窗口，否则 `-32010 no-grant` | `[码] index.js:1355` |
| `broadcast` 语义变化 | **不变**：仍是 `trusted` 全集、仍拒写入类、零投递仍抛 `-32008` | `[码] server.js:297-339` |
| 要不要"定向广播" | **不做**。要定向就循环 `request()`；给广播加 `targets` 会造出第二个路由口径 | 本条为设计决定 |
| 窗口元数据算不算敏感 | 工作区路径算敏感信息 ⇒ `list()` 与既有读能力同档位（`read`），未准入连接收不到 | `[码] whitelist.js:58` |

## 5. 错误码

新增 **`-32014` `WINDOW_TARGET_FAILED`**（一个码 + `data.reason`，与既有 `-32010` 用 7 个 reason 的形状一致 `[码] grant.js:548-651`）。本设计**不占** `-32011`；该码后来被 T62/A2 占为 `document-dirty`（`[码] packages/dsh-vscode-kit/src/protocol.js:78`，契约 §11），与窗口寻址无关。

| reason | 触发条件 | 调用方该做什么 |
|---|---|---|
| `window-not-found` | target 解析不到任何 `trusted` 活连接 | 调 `windows.list()` 重新发现 |
| `window-closed` | 曾有该 `windowId`，解析到的记录/连接已 `closed`/`destroyed` | 同上；别重试同一个号 |
| `window-ambiguous` | target 是 `label` 或过期的 `windowId`，命中 >1 个（同工作区两窗口 `stable:false` 时） | 改用 `connSeq` 写法（`#3`） |
| `target-unauthorized` | 读路径同时给了 `sessionId`（绑定读）与 target，且两者不是同一条 link | 去掉其中一个；绑定读以 grant 为准 |
| `target-not-routable` | 写路径带了 `target` | 去掉 target；写目标由 `grant()` 决定 |

判定顺序（先命中先返回）：`写? → target-not-routable` → `解析不到 → window-not-found` → `已关 → window-closed` → `命中多条 → window-ambiguous` → `绑定读冲突 → target-unauthorized` → 放行。
**破坏性说明**：新增 `ERR_NAME` 条目属纯新增（契约 §4.1 明列"加新能力/加 error `data` 字段"不算破坏）`[文档]`；但 `-32014` 一旦发布就不可复用。
