## 1. 十条步骤（每条三行：怎么操作 / 该看到什么 / 失败长什么样）

> 通用判据：任何一条事件行里如果出现 `"stale":true`，先看 `reason`：
> `event-too-large` / `snapshot-too-large` / `queue-overflow` / `missing-baseline` 属于
> 设计内降级；**日常手工编辑出现 `unsupported-change-basis` 就是缺陷**（意味着多 change 的
> 基准没通过重放校验），必须记进第 5 节。

### S1 手动键入多行

- **怎么操作**：打开 `probe-unicode.txt`，光标放到第 1 行末尾，键盘敲回车，再敲 `abc`，停手 1 秒。
- **该看到什么**：两行 `documentChanged`（回车一次、`abc` 三次可能合并）。`changeKind:"content"`，
  `changeCount` ≥ 1，`changes[0].rangeOffset` 等于第 1 行的 UTF-16 长度，`changes[0].text` 是
  `"\n"` 与 `"abc"`；`beforeVersion` 比 `afterVersion` 小；`incarnation` 与之前 `documentOpened`
  的**完全一样**；`textLength` = 你刚才用 `node -e` 算出的 UTF16 值（不是 UTF8 字节数）。
- **失败长什么样**：① 完全没有 `documentChanged` 行（采集没接上）；② 出现
  `"reason":"unsupported-change-basis"`（正常键入被判成不可重放 = 坐标基准出问题）；
  ③ `rangeOffset` 比预期大 1（把 `\n` 或 `\r` 多算/少算）；④ `textLength` 等于 UTF-8 字节数
  （UTF-16/UTF-8 混用）；⑤ 两次事件的 `incarnation` 不同（采集器自己发了化身）。

### S2 粘贴多行

- **怎么操作**：从别处复制 5 行普通文本（**用鼠标/键盘复制粘贴**），粘贴到文件末尾。
- **该看到什么**：通常**一条** `documentChanged`，`changeCount:1`，`changes[0].text` 是那 5 行原文
  （含换行），`textLength` 与 `text` 的 UTF-16 长度一致。
- **失败长什么样**：`changeCount` 标 1 但 `changes` 里的 `text` 被截断（冒充完整）；或
  `"stale":true,"reason":"event-too-large"` 出现在 5 行文本上（明显不该超 256 KiB）；
  或出现 `textOmitted:true`（说明信任/路径判定把你这个受信任文件判成了不许发）。

### S3 多光标

- **怎么操作**：`Alt+Click` 加 3 个光标到 3 个不同行（或 `Ctrl+Alt+↓` 加行光标），
  然后同时敲一个字符。
- **该看到什么**：一条或数条 `documentChanged`，`changeCount` 等于光标数；`changes[]` 里每项的
  `rangeOffset` 互不相同且**按降序排好**（offset 大的在前）；同时 50 ms 内合并出一条
  `selectionChanged`，`selections[]` 有 3 项，每项 `start`/`end`/`anchor`/`active` 的
  `line` 从 1 开始、`column` 从 1 开始（1-based，不是 0-based）。
- **失败长什么样**：`changes` 数量与光标数不符（丢了一次变更）；`line`/`column` 出现 0
  （漏了 +1）或比预期大 1（做了第二次转换）；排序不是降序。

### S4 undo / redo

- **怎么操作**：`Ctrl+Z` 撤销上一步，再 `Ctrl+Shift+Z` 重做。
- **该看到什么**：每次一条 `documentChanged`，`changeKind:"content"`；撤销那条的 `changes[0].text`
  应为空串（重做则恢复原文）；`beforeVersion`/`afterVersion` 每次递增；`incarnation` 不变。
- **失败长什么样**：撤销后出现 `"stale":true,"reason":"missing-baseline"`（基线丢了 —— 说明缓存
  被不该清的时候清了）；或 `afterVersion` 没变化却报了 content 变更。

### S5 选区拖动

- **怎么操作**：按住鼠标从第 1 行行首拖到第 2 行行尾（**拖动过程中不要松手太快**，拖 1 秒）。
- **该看到什么**：**远少于**拖动次数条 `selectionChanged`（50 ms 合并，实测应是每 50 ms 最多 1 条，
  松手后再来 1 条即止），字段是 `start`/`end`/`anchor`/`active`（1-based）；`viewId` 形如 `view-1`，
  同一编辑器稳定不变；**任何 `selectionChanged` 里都不要出现文档正文**（选区事件永远不带正文）。
- **失败长什么样**：一条都没有（监听没注册）；每秒几十条（合并没有生效，定时器变成每事件一个）；
  `selectionChanged` 里出现 `text` 字段（选区路径泄漏正文）；`viewId` 每次事件都变（视图 id 不稳定，
  会导致合并失效）。

### S6 滚动

- **怎么操作**：在同一个文件里让内容长到超过一屏（先粘贴 100 行），滚轮上下滚几屏。
- **该看到什么**：滚动过程中出现 `visibleRangesChanged`，带 `viewId` 与 `ranges[]`（1-based），
  频率同样被 50 ms 合并；停止滚动后不再有新行。
- **失败长什么样**：滚完还在每 50 ms 冒一条（合并表没清空 / 定时器泄漏 —— 停下来数 5 秒还不停
  就是泄漏）；或 `ranges` 里混进了正文。

### S7 拆分页签（split editor）

- **怎么操作**：`Ctrl+\` 把当前文件分成左右两个编辑器，然后在**右边**那个里敲一个字；
  再按 `Ctrl+W` **只关掉右边**这一个。
- **该看到什么**：① 拆分与打字时出现 `activeEditorChanged`（带新的 `viewId`，和左边不同）与
  `documentChanged`（`incarnation` 与拆前**相同** —— 同一个文档对象）；② 关掉右边时出现
  `tabsChanged{closed:[{files:[...],viewColumn:2,...}]}`，**不得**出现 `documentClosed`（左边还开着）。
- **失败长什么样**：关掉一个 split 就冒 `documentClosed`（把页签关闭当成文档关闭 —— 典型伪造就
  是这个）；或拆分后 `incarnation` 变了（把「视图」当成了「文档」）；或两个编辑器的 `viewId` 相同
  （多 view 被合并成一个）。

### S8 preview 替换

- **怎么操作**：在资源管理器里**单击**（不是双击）另一个文件 `probe-crlf.txt`，让它在同一个
  编辑器组里**替换**掉旧的 preview 页签（旧页签名字是斜体）。
- **该看到什么**：`tabsChanged{opened:[新文件…], closed:[旧文件…]}`；`documentOpened` 里新文件的
  `incarnation` 是**全新**的值。`documentClosed` 允许出现 —— 但只在 VS Code 真的销毁了旧文档模型时
  （旧文件此刻已没有任何 view）。判据是「有没有别的 view 还开着」。
- **失败长什么样**：旧文件**仍然开在另一个 split 里**却出现它的 `documentClosed`（伪造）；
  或只看到 `documentClosed` 而**没有** `tabsChanged`（把页签生命周期漏采，只留下了文档生命周期）。

### S9 关页签再重开

- **怎么操作**：`Ctrl+W` 关掉 `probe-unicode.txt`（此时它一个 view 都不剩），然后从资源管理器
  双击重新打开它。
- **该看到什么**：关的时候 `documentClosed` **只出现一次**（带最后的 `incarnation`）；重开时
  `documentOpened` 一条，`incarnation` 是**新值**（与关闭前那个不同），`version` 从 1 重新开始，
  `isDirty:false`。此后第一次打字带来的 `documentChanged` 用的是**这个新** `incarnation`。
- **失败长什么样**：同一次关闭冒出两条 `documentClosed`（没去重）；重开后 `incarnation`
  与关闭前相同（复用了已销毁文档的身份）；重开后第一次 `documentChanged` 报
  `"reason":"missing-baseline"`（重开时没重建基线）。

### S10 两窗口交替获得焦点

- **怎么操作**：另开一个 VS Code 窗口（`Ctrl+Shift+N`）也打开同一个工作区，然后在两个窗口之间
  点来点去 3 次。
- **该看到什么**：每次焦点切换，**被点中的那个窗口**输出一条 `windowFocusChanged{focused:true}`，
  另一个窗口对应的行是 `focused:false`；同一文件在两个窗口各有一条 `documentOpened`，
  两个 `incarnation` **不同**（不同窗口是不同文档对象）；`describeWindow` 里的 `sessionId`
  在两窗口间不同。
- **失败长什么样**：切 3 次只看到 1~2 条（窗口状态监听漏注册）；两窗口的同一文件 `incarnation`
  相同（跨窗口串了身份）；或焦点切换后**事件行成倍增加**（每次 activate 都叠了一层监听 ——
  这就是监听器残留）。

## 4. 两条红线

1. **不得用第二次桥接 `applyEdit` 冒充人工输入。** 本清单里所有「敲、粘贴、拖动、滚动、
   切焦点」必须由**人手**在真实编辑器里产生。用桥接的 `applyEdit` / 编辑事务回灌同样可以
   造出 `documentChanged`，但那是另一条通路（写事务自带锚点与版本），它证明不了 E2 在
   **真实 InputEvent / 真实 `contentChanges`** 上的正确性 —— 用它代劳的那一步作废，
   必须重做。
2. **本清单尚未由人执行，属待验证。** 清单里的每一条「该看到什么」都是从源码与单元测试
   推出的**预期**。在有人按本清单跑完并把第 5 节填起来之前，E2 的结论只能是
