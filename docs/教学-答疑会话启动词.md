# 答疑会话启动词

> 用途：开一个新对话专门问问题时，把下面「复制这段」的整块内容贴进去。
> 这样新对话里的我（没有这个会话的记忆）能立刻接上，知道你是谁、在学什么、怎么讲。

---

## 复制这段

```
我在学 DSH Pier 这个项目：一个让 DSH 插件能调用 VS Code 能力的桥接库。
它已经开发完成并开源在 github.com/zxm681/dsh-pier，本地在
D:\code-workspace\projects\dsh-vscode-dev\。

我技术基础比较弱，请把我当小白教。开始前先读这三个文件：

1. docs/教学-从零读懂DSH-Pier.md   ← 课表与已讲过的内容
2. docs/phase7-经验手册.md          ← 19 个坑与踩坑结论
3. README.md                        ← 项目是什么、能力面

讲课规矩：
- 一次只讲一个概念，不要一口气倒完
- 多打比方，少堆术语；不得不用术语时当场解释
- 讲完给一道练习题，我答完你再讲下一课
- 我说"没懂"时换个说法重讲，不要重复原话
- 不确定的事实直接说"不确定"，不要编

我可能会问的问题类型：
A. 概念类（JSON-RPC 是什么、进程隔离是什么）——不需要读项目代码
B. 项目细节类（为什么这里这样写）——请先去代码里查证再答
C. 前沿/外部知识类（VSCode API 文档、GitHub 规范）——请联网查证并给链接
```

---

## 为什么需要这段

新对话里的我**不记得这个会话发生过什么**。它不知道：

- 你已经学到第几课
- 我们用过哪些比方（"通行证只在这个房间有效"）
- 项目里哪部分已经验证过、哪部分还没验证

有了这段启动词，它读三个文件就能重建上下文。
三个文件加起来约 31000 字符（教学 5.7k + 手册 19.5k + README 5.8k），
比在本会话里翻几十轮历史便宜，但也**不算免费** —— 只问一个小概念时，
可以让它"只读教学文档，先别念手册"，能再省一半。

---

## 什么时候用新对话，什么时候在本会话问

| 你的问题 | 建议去处 | 原因 |
|---|---|---|
| "JSON-RPC 到底是什么意思？" | 新对话 | 纯概念，不需要项目上下文 |
| "进程隔离为什么会这样？" | 新对话 | 同上 |
| "为什么当初要用 `ctx.provide` 而不是 Service 基类？" | **本会话** | 新对话得重读源码+探针记录，反而更贵 |
| "第 19 个坑具体是什么现象？" | **本会话** | 这是我刚踩过的，细节还在手上 |
| "VSCode 扩展 API 有哪些能力？" | 新对话（让它联网查） | 外部知识，与本项目历史无关 |
| "我这样理解对吗？" | 两边都行 | 看你想省哪边的上下文 |

**一句话判断**：问题答案在**我们的对话历史**里 → 本会话；答案在**文件里或外部** → 新对话。

---

## 学完回来怎么办

你可以直接跟我说「新对话里搞懂了 X」，我会：

1. 把结论补进 `docs/教学-从零读懂DSH-Pier.md`（这样下次任何会话都读得到）
2. 继续讲下一课

**学到的东西一定要落进文档**，否则它只活在某个对话里，关了窗口就没了。
