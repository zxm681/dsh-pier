## 三、gpt 判卷的结论（今天刚做的，必须落地）

派 `code-reviewer`（gpt-6.1-sol）核实 `backend-engineer`（deepseek-flash）上一轮对 `protocol.js` 的 4 条结论。**两条被判定"部分成立"，措辞需要修正**：

| 原结论 | gpt 判定 | 要改什么 |
|---|---|---|
| ① `notify`/`respond` 默认不带 token | **成立** | 不用改 |
| ② `request()` 无条件带 token，「文档未说明差异」 | **部分成立** | **`protocol.js:91` 已明确写着「每个出站请求自动附带」**，所以「文档没写」这半句是错的。不能概括成「所有出站消息默认不带」 |
| ③ `respondError` 缺 token 通道，与 `:198` 文档「矛盾」 | **部分成立** | `:198` 原文描述的是 `respond`，说「已证明的安全矛盾」**夸大了**，准确表述是「错误响应缺少对应能力」。且必须强调：**绝不能给未认证者的 -32001 附送凭据** |
| ④ handler 可能把 `ctx.token` 写进 result | **部分成立，不值得修** | token 来自**对方刚发来的消息**，不是闭包保存的本地秘密，原连接回传不新增泄密。真要修应修具体数据流，别递归清洗任意 result |

**gpt 还推翻了一条「好的一面」**：deepseek 说「`send` 未导出，外部无法自行发包」——gpt 指出底层 writer 本来就是**调用方注入**的（`protocol.js:86-99`），那不是隔离恶意调用者的安全边界。

### 7.2 拆分到底改了什么（读代码核的，不是照抄描述）

| 位置 | 事实 |
|---|---|
| `server.js:124` | `const links = new Set()` —— **所有**活 socket 的存活登记，只用于存活成员校验、诊断计数和 `close()` 时销毁底层 socket；**不作请求/广播目标池**。 |
| `server.js:126` | `const trusted = new Set()` —— 只收「至少发过一条 token 正确的消息」的连接，是**唯一**可选请求目标。 |
| `server.js:159` | `trusted.add(link)`，注释明写「先升格，再同步通知」。 |
| `server.js:172-173` | `close` / `error` 两条路径都双删 `trusted` 与 `links`。 |
| `server.js:178` | `link.connSeq = ++connSeq` —— 序号在**建连那一刻**定死，与「第几条准入」完全无关。 |
| `server.js:245` | `for (const link of trusted) link.notify(method, params)` —— `broadcast()` 只发已准入连接（有意收紧的契约变更：未准入连接不该收到可能含选区文本的通知）。 |
| `index.js:78-93` | `_activeLink()` 只遍历 `this.server.trusted`，取 `connSeq` 最大**且 `socket` 未销毁**的那条；**不回退 `links`**。 |

`link.authorized` 只留作诊断/兼容，**不再承担安全边界**（§5.9 里那句 `links.filter(authorized)` 是拆分前写法，已过时）。

**评审抓到的偏移回归（R1，这条最容易漏，必须记住）**：最初实现是「取 `trusted` 末项」。`trusted` 在**首次准入**时 add，末项 = 「最后**准入**」；而拆分前 `links` 在建连时 add，取末项 = 「最后**连接**」。两者都合法时口径会漂：

```
connect A → connect B → 先准入 B → 后准入 A
旧算法（links 末项）：B        只取 trusted 末项：A
```

于是 `vscode.openFile` 会送到另一个编辑器窗口——这是一个**没人批准过的契约变更**。评审第 1 轮判 `needs_revision` 抓住它，返工任务 T12 改成显式 `connSeq`，第 2 轮 `pass`。回归测试守在 `test/apply.test.js:187`（纯内存：按序号不按插入序）、`:232`（A/B 逆序准入仍选后连接的 B）、`:256`（目标断开后回退次新），另有 `:175` / `:301` / `:330` / `:356` 四条「裸连接/错 token 抢不到位」的安全回归。
