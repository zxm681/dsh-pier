### 1.2 provider 支持（插件打了补丁）

**问题**：`expert-profiles.json` 原本只支持 `model`，不支持 `provider`。所以 `model: "gpt-6.1-sol"` 只换模型名、provider 仍走默认 `deepseek-official` → deepseek 那边没有这个模型 → **summon 直接失败（stopReason=error）**。

**证据链**：
- 宿主 schema：`dsh-tool-subagent/lib/index.js` → `agentOptions: z.object({ provider: z.string(), model: z.string(), reasoningEffort: z.string().min(1), maxTokens: z.number() })` —— provider 与 model 是**两个独立字段**
- 插件原字段表：`EXPERT_PROFILE_FIELDS = ['model','tools','skills','mcp','effort']` —— **没有 provider**

**补丁（三处，已生效，需重启才加载）**：

| 文件 | 改动 |
|---|---|
| `lib/expert-profiles.js:54` | FIELDS 加 `'provider'` |
| `lib/expert-profiles.js:90-93` | 新增 `parseExpertProfile` 的 provider 解析分支（形状同 model 分支） |
| `lib/effort-preflight.js:39-44` | 前置判断加 `&& !profile.provider`；新增 provider 分支（放在 model 分支**之前**） |

**备份**（回滚用）：

**验证过**：`preflightEffort` 三组输入断言全过——`{model,provider}` → 两个键都带；`{model}` only → 只带 model（向后兼容）；`caps.agentOptions=false` → undefined + warning。

## 三、gpt 判卷的结论（今天刚做的，必须落地）

派 `code-reviewer`（gpt-6.1-sol）核实 `backend-engineer`（deepseek-flash）上一轮对 `protocol.js` 的 4 条结论。**两条被判定"部分成立"，措辞需要修正**：

| 原结论 | gpt 判定 | 要改什么 |
|---|---|---|
| ① `notify`/`respond` 默认不带 token | **成立** | 不用改 |
| ② `request()` 无条件带 token，「文档未说明差异」 | **部分成立** | **`protocol.js:91` 已明确写着「每个出站请求自动附带」**，所以「文档没写」这半句是错的。不能概括成「所有出站消息默认不带」 |
| ③ `respondError` 缺 token 通道，与 `:198` 文档「矛盾」 | **部分成立** | `:198` 原文描述的是 `respond`，说「已证明的安全矛盾」**夸大了**，准确表述是「错误响应缺少对应能力」。且必须强调：**绝不能给未认证者的 -32001 附送凭据** |
| ④ handler 可能把 `ctx.token` 写进 result | **部分成立，不值得修** | token 来自**对方刚发来的消息**，不是闭包保存的本地秘密，原连接回传不新增泄密。真要修应修具体数据流，别递归清洗任意 result |

**gpt 还推翻了一条「好的一面」**：deepseek 说「`send` 未导出，外部无法自行发包」——gpt 指出底层 writer 本来就是**调用方注入**的（`protocol.js:86-99`），那不是隔离恶意调用者的安全边界。

## 五、已知限制（诚实清单）

1. **本机不是安全边界**。token 防的是「本机别的进程冒充编辑器」，不防「本机进程读你的文件」——同用户下任何程序都能读发现文件拿到 token。这是设计取舍，已写进 README。
2. **`.dsh/expert-profiles.json` 的项目层**是 `<cwd>/.dsh/expert-profiles.json`。**换工作区 = 换项目层**。全局层在 `~/.dsh/expert-profiles.json`（当前配置在这里）。
3. **`architect-reviewer` 是外部来源专家**（awesome-claude-code-subagents），来源文件缺失时叫不出来。
4. **编排协议的自动认领**（`taskboard.py` auto-claim）需要 python3 可用——已修，但若 Python 重装需重做。
